梦鱼更新器是为广大 Minecraft 模组服设计的管理工具。开模组服的腐竹们应该都知道：模组出了 Bug，或者服务器崩服需要删改内容时，处理起来有多痛苦。一方面，你要清楚地告诉玩家该如何处理有问题的模组；另一方面，如果服务器有自制模组需要频繁更新，每次都让玩家手动修改，实在让人头疼。你可能还想给自己的服务器设计一个酷炫的启动客户端，在里面展示新闻、公告以及更多内容……因此，我们制作了梦鱼更新器。它是一个更新器，也可以成为你的服务器专属客户端。

梦鱼更新器是一个安全可靠、自主可控、易于部署的 Minecraft 客户端管理工具：服主可以用 Web 或可交互终端管理项目与发布，玩家端在启动前自动更新，玩家自己的模组和文件也始终保有清楚的控制权。

## 它能帮你省掉哪些麻烦

以前更新整合包，往往要重新压缩一整个客户端，再告诉玩家下载、解压和覆盖。遇到模组冲突或紧急修复时，还得反复解释“删哪个文件、换成哪个版本”，玩家只要漏做一步，就可能进不了服务器。

使用梦鱼更新器后，流程会简单很多：

1. 你只需要维护一份作为标准的整合包目录，像平时一样添加、替换或删除文件。
2. 管理端会帮你扫描出这次有哪些变化。确认列表没有问题后，点击发布即可。
3. 玩家仍然照常从 PCL、HMCL 等启动器进入游戏，更新器会在启动前自动检查。
4. 玩家只会下载真正发生变化的文件，不需要每次重新下载整个整合包。
5. 文件替换前会先完成校验和备份；即使更新中断或失败，也会尽量恢复原来的客户端，不会留下更新到一半的状态。
6. 一切完成后，Minecraft 会继续启动，玩家不需要再手动处理文件。

你也不需要维护“1.0 先升级到 1.1，再升级到 1.2”这样的补丁顺序。每次发布都会说明最新版客户端应该包含哪些内容，所以即使玩家跳过了中间几个版本，也可以直接更新到最新版本。

## 核心能力

| 功能 | 使用时有什么用 |
| --- | --- |
| 只更新有变化的文件 | 玩家不必反复下载整个整合包。多个文件可以同时下载，大文件中断后也能接着传。 |
| 防止文件损坏或被替换 | 玩家端会检查发布签名、文件大小和 SHA-256；文件下载损坏或内容被人替换时，不会直接安装。 |
| 更新失败可以恢复 | 新文件会先下载到临时位置，校验并备份完成后才正式替换。中途退出或安装失败时，会尽量恢复到更新前的状态。 |
| Web 与可交互终端管理 | 创建项目、管理文件、预览变化、发布与回滚、制作首次部署包等操作既可以在网页中完成，也可以在服务器终端中完成。 |
| 玩家也能管理自己的文件 | 对于没有强制同步的内容，玩家可以停止管理某个文件或目录，也可以启用、停用自己的模组；这些选择只保存在玩家电脑上。 |
| 玩家端程序自动更新 | 服主发布新版玩家端后，旧版会在下次启动时自动更新，不需要为了一次界面或程序升级重新分发整个整合包。 |
| 支持外部托管和 CDN | 服务器带宽不够时，可以把更新内容导出或上传到 WebDAV、OSS、S3、R2 等存储，再交给普通 HTTP 或 CDN 分发。 |
| 做成服务器专属客户端 | 可以设置服务器名称、封面、标题、副标题、主题颜色，还能添加公告、新闻、规则、玩法等自定义页面。 |
| 更新服务器离线时仍可启动 | 如果玩家上一次已经完整更新并通过检查，更新服务器临时离线时仍可使用最近一次的有效客户端；真正的文件校验错误不会被当成普通断网跳过。 |

## 贴心的两种同步模式——普通同步和强制同步

第一次使用时，建议先保持普通同步。只有确认某个文件或目录必须与服务器完全一致时，再把它设为强制同步。

| 对比 | 普通同步（建议先用） | 强制同步（确认需要后再开） |
| --- | --- | --- |
| 适合什么内容 | 大多数模组、配置、资源包，以及允许玩家自行调整的内容 | 核心模组、关键配置、服务器连接组件等不能被玩家修改或停用的内容 |
| 服主发布的文件 | 文件缺失或发生变化时会自动更新；玩家也可以在自己电脑上将普通内容设为不再管理 | 文件缺失、被修改或版本不一致时都会恢复为服主发布的版本，玩家不能豁免或停用 |
| 玩家自己添加的文件 | 不在发布列表中的文件和模组会保留，不会因为更新被顺手删除 | 如果强制的是整个一级目录，目录内不属于发布内容的文件会先进入玩家归档，再移出游戏实例 |
| 可以设置多大范围 | 没有设置强制规则的托管内容都按这种方式处理 | 可以只强制一个具体文件，也可以强制 `mods`、`config` 这样的整个一级目录 |
| 对其他文件的影响 | 只维护服主明确发布的内容 | 强制单个文件只锁定这个文件；强制整个目录才会检查并整理目录中的所有额外文件 |

简单来说：如果只是希望某个核心模组不能被修改或停用，就强制同步这一个文件；如果希望玩家的整个 `mods` 目录都和服务器发布的版本完全一致，才强制同步整个 `mods` 目录。不确定时，保持普通同步最稳妥。

当你从标准目录中移除普通托管文件时，可以在发布前选择“让玩家端删除”或“放弃管理并保留玩家副本”。玩家自己的本地豁免只影响自己的电脑；强制同步内容则必须跟随服务器发布结果。

## 玩家端的启动流程

玩家仍然从自己熟悉的 Minecraft 启动器启动游戏。Agent 会拉起 DreamingFish 玩家端，玩家能清楚看到本次检查、下载进度、更新记录和启动状态；检查完成后，Minecraft 照常继续启动。

玩家端同时提供：

- 本次更新、更新记录与运行记录；
- 按目录或单文件管理本地内容；
- 服务器模组与玩家自选模组的独立启停；
- 服主自定义的公告、活动、玩法、规则和世界观页面；
- 与服务器风格一致的名称、封面、强调色和首页介绍。

普通同步下的本地选择不会上传到服务器。

## 基本使用流程

管理端可以运行在 Windows 或 Linux 服务器上，既能使用 Web 页面，也能通过可交互终端管理。

1. 运行管理端并跟随首次引导完成设置。
2. 创建项目，选择要管理的文件目录，并填写玩家可以访问的更新地址。
3. 添加或修改 `mods`、`config` 等内容，扫描变化后创建发布。
4. 发布玩家端程序，生成首次部署包，并按教程接入 PCL 或 HMCL。
5. 完成一次实际启动测试后分发给玩家；以后的更新由玩家端在启动游戏前自动完成。

首次部署、远程 Web 管理、启动器参数和外部托管等具体操作，请直接跟随[官网完整教程](https://dreamingfish-studio.github.io/DreamingFish-Updater-Website/)。

## 兼容与安全

- 玩家可以继续使用 PCL 或 HMCL，支持管理 Forge、NeoForge 和 Fabric 整合包；梦鱼更新器不会接管账号登录、游戏下载或 Java 选择。
- 正式发布带有签名，每个文件都会校验大小和 SHA-256；文件损坏或被替换时不会直接安装。
- 更新前会暂存新文件并备份旧文件，中断或失败时会尽量恢复，不留下更新到一半的客户端。
- Web 管理页面包含发布和文件管理权限，远程使用时请按照官网教程配置 SSH 隧道，或启用账号与 HTTPS 保护。
