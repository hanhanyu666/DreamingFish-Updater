# [玩家 - 0.3.5][管理 - 0.3.4] 修复背景预览与同步，改进任务清单

**服主需要把新版玩家端程序 0.3.5 发布给已有玩家，玩家才能收到发布后的新背景。在管理端“发放 → 玩家端程序”检查官方新版并发布，使用 OSS / WebDAV 的还需完成上传。仅升级远程管理服务不会替换服主电脑上的旧桌面程序，桌面版请另外升级。**

玩家端升级为 **0.3.5**，管理端与桌面版升级为 **0.3.4**，Bootstrap Agent 继续使用 **0.1.2**。

## 更新内容

- 修复上传自定义背景后缩略图或实时预览未显示新图的问题。
- 玩家端按已发布版本获取并校验背景图片，支持换图和恢复默认背景。暂时下载不到新图时，模组和配置仍可继续更新。
- 管理端顶部新增“任务清单”入口，分别显示后台任务和导入文件。任务结果待核对时，可以查看原操作对应的页面，刷新后会显示查询结果。
- 关闭待核对提醒时，确认按钮直接显示在任务卡片内。关闭提醒只移除提示，不会重新执行原任务。

## 更新教程

### 升级前备份

1. 等待导入、发布、上传和玩家程序下载完成，再停止旧管理程序。桌面窗口关闭后通常仍在托盘运行，手动替换程序前通过托盘菜单或连接页的“退出桌面端”彻底退出。
2. 在桌面连接页点击“数据目录”，确认实际管理目录。终端用户按原服务的启动参数确认数据位置。备份该目录中的 `data/`、`management-settings.json`、`management-web-auth.json`（已有账户时）、项目签名身份、日志和恢复记录。
3. 备份桌面连接记录、外部管理目录和标准整合包源目录。使用单独的加密发布备份时，也要保留以上完整备份。原有私钥和身份文件随管理数据一起保管。

### Windows 桌面安装版

1. 在桌面连接页点击版本号检查更新，发现 0.3.4 后按提示安装。自动更新结束后重新打开原连接。
2. 手动安装时，下载 `dfs-admin-desktop-windows-x64-0.3.4-setup.exe`，彻底退出旧桌面程序，再运行安装包并沿用原安装位置。安装时保留原管理数据。
3. 确认桌面版本显示 0.3.4，原项目、账户和发布历史完整。本机管理核心随桌面一起更新，单独运行在服务器上的管理服务按下面的终端步骤升级。

### Windows 桌面便携版

1. 下载 `dfs-admin-desktop-windows-x64-0.3.4.zip`，完整解压到固定目录，在解压后的目录中运行程序。
2. 备份并彻底退出旧程序后，替换 EXE、`core/` 等程序资源，保留旧 `data/` 和连接记录。核对新旧目录后再替换，避免新包的空目录覆盖已有数据。
3. 搬迁安装目录时同时迁移原有数据，另外保留外部管理目录与整合包源目录。启动 `DreamingFishAdminDesktop.exe`，检查版本为 0.3.4，并打开原连接。

### Windows / Linux 终端管理端

1. 下载对应系统的 `dfs-admin-windows-x64-0.3.4.zip` 或 `dfs-admin-linux-x64-0.3.4.zip`。按原来的终端、服务管理器或启动脚本停止旧服务。网页管理与公共下载服务分开运行时，分别停止。
2. 解压后替换程序、`app/`、`runtime/`、`support/` 和配套启动脚本，保留原 `data/`、`management-settings.json`、`management-web-auth.json`、恢复记录及外部源目录。继续使用原来的监听地址、端口和反向代理配置。
3. 按原方式启动。Windows 运行 `.\DreamingFishAdmin.exe --version`，Linux 运行 `./dfs-admin --version`，应显示 0.3.4。Linux 解压后若缺少执行权限，给 `dfs-admin` 和 `runtime/bin/java` 补上执行权限。
4. 刷新管理网页，打开原项目，确认账户、历史和公共下载地址正常。

### 玩家端是否需要更新

1. **本次需要由服主发布玩家端程序 0.3.5。** 管理端 0.3.2 或更新版本中，打开“发放 → 玩家端程序”，点“检查官方新版”，确认版本为 0.3.5，再点“发布给玩家”并确认。管理服务会下载、核对并发布程序。
2. 手动发布时，下载 `dreamingfish-player-windows-x64-0.3.5.zip`，展开“手动上传玩家端发行 ZIP”，上传 ZIP，点击“检查发行包”，确认版本为 0.3.5、平台为 windows-x64，再点“批准并发布”确认发布。
3. 使用 OSS、WebDAV 或其他静态托管时，发布后执行“导出并上传”。已开启“发布后自动上传”的，检查本次上传成功后再让玩家测试。
4. 已有玩家下次联网打开更新器时会下载并切换到 0.3.5，随后检查整合包。服务器名称、背景、公告和玩家设置会保留。若服主暂停了玩家端升级，需要先完成新版发布并允许升级。
5. 使用新版程序即可获得背景修复，已部署实例继续沿用现有 Bootstrap Agent 和启动参数。普通在线更新沿用原整合包发布流程。

### 升级后检查

1. 核对实际使用的管理端及桌面版本为 0.3.4，原项目、账户、签名身份和发布历史完整。看到空项目或新建账户向导时，先核对连接及原数据目录，保留恢复材料。
2. 在“发放 → 玩家端程序”确认已发布 0.3.5。使用外部托管时确认上传成功，玩家更新地址可以访问。
3. 用一个测试实例联网打开更新器，确认自动升级到 0.3.5，并完成一次整合包检查。
4. 在“玩家端设计 → 外观与背景”上传一张图片，确认缩略图和实时预览可见。到“改动与版本”发布整合包后，用新版玩家端检查背景是否更新。首页焦点单独设置了图片时，请在对应的焦点页检查。
5. 打开管理端顶部的“任务清单”，检查任务状态能正常查询，公共下载服务已恢复运行。
