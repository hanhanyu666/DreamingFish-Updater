# [玩家 - 0.2.2][管理 - 0.2.6] 修复导入恢复与桌面任务，完善文件校验和资源管理

**要让已有玩家获得本次玩家端修复，服主还需发布 0.2.2 玩家端程序；仅升级管理端不会自动更新玩家电脑上的程序。旧版 0.2.1 仍可配合使用，但不具备这些修复；若将整合包的最低玩家端版本设为 0.2.2，玩家需先升级才能接受该发布。**

本次集中修复导入中断、数据迁移、项目切换和桌面任务状态问题，补齐玩家端文件校验与游戏运行保护，并减少不再需要的临时文件。管理端与管理端桌面版升级为 **0.2.6**，玩家端升级为 **0.2.2**，Bootstrap Agent 保持 **0.1.2**。

## 管理端与桌面版

- 切换项目时，上一项目迟到的响应不再覆盖当前界面；已打开的编辑和导入操作也固定属于原项目，避免看着一个项目却修改另一个项目。
- 导入支持明确跳过和结果复查。断网或回执丢失后，先确认原操作是否成功，不再直接重复导入；文件已导入但随后检查失败时，也能正确显示实际结果。
- 导入和撤销会提前记录恢复信息，程序中断后可以继续恢复；复制一半的临时文件可以安全重建，后来手动修改过的文件仍受到保护。
- 修复桌面任务已经完成却一直显示排队、无法切换项目的问题；另一个终端查询任务时，不再把仍在执行的任务误判为异常。
- 修复冲突重试可能删除原有有效暂存的问题；失败只清理本次新建且未完成的上传。
- 数据迁移增加恢复记录与内容核对，失败后能确定实际数据位置；连接配置损坏时保留原件和可恢复备份。
- 程序目录内的管理路径改用相对记录，便携版移动后更容易继续使用；外部目录仍保持独立，旧路径有歧义时要求重新定位。
- 下载与管理请求分开处理，限制连接、排队和停滞时间；桌面断开连接会取消所属请求，避免慢下载长期占满管理请求资源。
- 增加存储统计、配额和清理预览；已完成导入不再长期保留多余的大文件副本，必要的收据、撤销归档与历史发布继续保留。
- 文件目录提前汇总并按页显示，减少大项目中反复遍历目录的开销；管理界面使用系统中文字体，减少首次加载资源。
- 统一桌面页面故障的自动恢复次数，反复失败后停止重试，并提供手动恢复入口。

## 玩家端

- 完整校验和严格离线许可会检查实际文件内容，不再仅凭文件大小与修改时间认定文件没有变化。
- 游戏运行时，更新引擎不会提交修复、恢复或维护状态修改，避免离线流程绕过游戏运行锁。
- 收紧展示内容、预览消息与原生命令的访问边界，并更新可修复的依赖问题。

## 维护与性能

- 复用管理服务实例、拆分部分请求处理逻辑，统一后台任务协议，补充跨进程恢复与真实桌面链路测试。
- 增加构建资源一致性检查、发行包审计和 Windows / Linux 验证配置；同步使用文档、能力矩阵和存储说明。
- 性能有升有降：重构阶段同机三轮测试中，约 1 万文件的列表查询从 2.69 秒降到 1.83 秒；约 256 MiB 首次发布从 85.4 秒增加到 100.0 秒，16 MiB 导入也增加约 1.4–2.3 秒。不能把本次更新理解为全面提速。
- 上述性能数据早于最后四项补修，不是最终发行包的完整性能复测。测试场景与限制见[性能记录](https://github.com/hanhanyu666/DreamingFish-Updater/blob/v0.2.6/docs/reviews/2026-10-18-performance-results.md)；没有据此声称 Minecraft TPS、玩家下载速度或服务端常驻内存得到改善。

## 升级说明

- Windows 桌面用户使用安装包或便携包；终端管理端提供 Windows / Linux 包；玩家端提供 Windows 包。
- 升级前保留管理数据、账户、签名身份、桌面连接和外部标准整合包目录。不要用新包中的空目录覆盖已有数据，也不要删除恢复记录来绕过冲突。
- 服主需要发布 **0.2.2 玩家端程序**，已有玩家才能通过程序更新获得本次玩家端修复；仅升级管理端不会自动替换玩家电脑上的程序。
- 管理数据与恢复格式有更新，勿用旧管理程序修改升级后的数据；需要退回时使用升级前的完整备份。
- Windows 桌面仍按试用范围使用；自动化验证不代表已经覆盖真实 RTSS 注入、所有安装升级环境或硬断电。
