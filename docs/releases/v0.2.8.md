# [玩家 - 0.2.2][管理 - 0.2.8] 修复部署包下载，新增另存为与保存结果提示

**本次只更新管理端与桌面版，玩家端保持 0.2.2，不需要重复发布玩家端程序。要获得部署 ZIP 的本机另存为和保存结果提示，需要升级服主电脑上的桌面程序；仅更新远程管理服务不会替换旧桌面程序。**

管理端与桌面版升级为 **0.2.8**，玩家端保持 **0.2.2**，Bootstrap Agent 保持 **0.1.2**。

## 修复与改进

- 桌面端生成部署 ZIP 时先选择本机保存位置，文件完整保存后显示路径、大小和“打开所在文件夹”。连接远程服务器时，文件也保存在运行桌面程序的电脑上。
- 取消保存不会开始生成或下载。生成失败、网络中断和写入失败会显示错误，不再把“收到 ZIP、触发下载”当作“文件已经存进电脑”。
- 部署包分块下载到临时文件，完整写入后再替换目标 ZIP；失败时保留已有同名文件，清理此次未完成的临时文件，避免在桌面网页内存里缓存整个部署包。
- 新网页在浏览器支持时提供“另存为”，写入完成后才提示已保存；其他浏览器和旧网页明确提示去浏览器下载列表查看保存位置、进度和拦截原因。
- 每次 Release 都保留完整更新教程。发布脚本会检查教程各部分和需要保留的数据，缺少教程或只有空标题时拒绝上传。

## 更新教程

### 升级前备份

1. 等待导入、发布和部署包下载完成，再进行升级。关闭窗口通常只是隐藏到托盘；需要替换程序文件时，使用连接页“退出桌面端”或托盘退出，让旧进程真正结束。
2. 桌面用户先在连接页点击“数据目录”，确认实际保存位置；另行备份自选的管理目录。终端用户备份实际管理端目录。保留 `data/`、`management-settings.json`、`management-web-auth.json`（已注册账户时）和桌面连接、日志与恢复记录；项目签名身份必须保留。
3. 外部标准整合包目录、外部管理目录也要单独备份。加密“发布数据备份”不能替代上述完整备份。不要用新包里的空目录覆盖已有数据，也不要把管理数据或签名私钥发给玩家。

### Windows 桌面安装版

1. 在桌面连接页点击底部的版本号“检查更新”，有新版本时选择“立即更新”，按提示关闭工作区并安装。自动更新完成后会重新打开程序。
2. 也可以下载 `dfs-admin-desktop-windows-x64-0.2.8-setup.exe`，完整退出旧桌面程序后运行安装包，沿用原安装位置。保留原数据，不要选择删除或重置管理数据。
3. 打开原来的连接，确认连接页版本为 **0.2.8**，原项目、账户和发布历史仍在。桌面自带的本机管理核心随程序更新；独立部署在服务器上的终端管理端需按下面的终端步骤另行升级。

### Windows 桌面便携版

1. 下载 `dfs-admin-desktop-windows-x64-0.2.8.zip`，完整解压到固定目录。不要直接在压缩包里运行，也不要只复制里面的 EXE。
2. 完整退出旧桌面程序并备份后，使用新版的程序文件、`core/` 等程序资源替换旧程序；保留旧目录内已有的 `data/`，不要拿新包中的空数据覆盖它。
3. 如果搬到新目录，连同原 `data/` 一起搬迁；原来放在外部的管理与整合包目录仍须保留，必要时重新定位连接。运行 `DreamingFishAdminDesktop.exe`，确认版本和原有项目正确。

### Windows / Linux 终端管理端

1. 下载对应系统的 `dfs-admin-windows-x64-0.2.8.zip` 或 `dfs-admin-linux-x64-0.2.8.zip`。先按原来的终端、systemd、Docker 或启动脚本方式停止管理端进程；不要在旧进程仍运行时混用新旧程序文件。
2. 解压新包，替换原目录中的程序、`app/`、`runtime/`、`support/` 和对应启动脚本；保留 `data/`、`management-settings.json`、`management-web-auth.json`、恢复材料及外部标准整合包目录。继续使用原有服务参数、端口和反向代理配置。
3. 按原方式启动。在管理端目录检查版本：Windows 运行 `.\DreamingFishAdmin.exe --version`，Linux 运行 `./dfs-admin --version`，确认输出 **0.2.8**；Linux 如解压工具没有保留执行权限，补上 `dfs-admin` 与 `runtime/bin/java` 的执行权限。
4. 重新打开或刷新管理网页，确认原账户、项目和发布历史。使用独立公共下载服务的，按原部署方式恢复服务并检查玩家更新地址。希望使用新的桌面另存为时，还需升级自己电脑上的桌面程序。

### 玩家端是否需要更新

1. **本次玩家端仍为 0.2.2，已经发布过这个版本的服主无需重复上传，也无需重新制作或发放整合包。** 本次修复在管理端，Bootstrap Agent 仍为 0.1.2。
2. 如果此前仍停留在 0.2.1，尚未交付之前的玩家端修复，可在管理端进入“发放 → 玩家端程序”，上传 `dreamingfish-player-windows-x64-0.2.2.zip`，点击“检查发行包”，确认识别的版本与平台后“确认发布”。已有玩家在下次联网运行更新器时取得已发布的程序更新。
3. 只有首次发放或制作新的完整整合包快照时，才需要生成薄部署 ZIP 并合并到对应实例；普通在线模组和配置更新继续走检查、发布流程，不必每次重新打包整个客户端。

### 升级后检查

1. 确认实际使用的管理端和桌面程序为 **0.2.8**，原项目、账户、签名身份及发布历史完整。若显示空项目或新建账户向导，先核对连接与数据路径，不要直接重新建库或删除恢复记录。
2. 在“发放 → 发放整合包”选择已发布版本，点击“生成并下载部署 ZIP”。桌面端应先出现保存窗口，保存后显示真实路径与文件大小，“打开所在文件夹”应能定位保存目录。
3. 再试一次取消保存，确认不会产生新 ZIP。网页用户按浏览器能力使用另存为，或到下载列表核对结果；出现拦截提示或失败时，按具体错误处理，不把“已交给浏览器下载”当作保存完成。
4. 检查公共下载服务与项目玩家更新地址，使用测试实例完成一次更新。签名、整合包维护规则和最低玩家端版本不需要因本次管理端更新而调整。

完整部署与故障排查可参考 [快速开始](https://github.com/hanhanyu666/DreamingFish-Updater/blob/v0.2.8/docs/QUICKSTART.md) 和 [部署参考](https://github.com/hanhanyu666/DreamingFish-Updater/blob/v0.2.8/docs/DEPLOYMENT.md)。
