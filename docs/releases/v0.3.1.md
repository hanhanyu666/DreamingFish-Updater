# [玩家 - 0.3.2][管理 - 0.3.1] 全新玩家端首页，服主可自定义展示内容

**本次玩家端和管理端都要更新。服主需要在管理端发布玩家端程序 0.3.2，玩家才会看到新版界面；只升级管理端时，玩家仍使用旧界面。新的展示内容编辑在桌面程序和管理网页里，仅升级远程管理服务不会替换服主电脑上的旧桌面程序，桌面版需要另外升级。**

管理端与桌面版升级为 **0.3.1**，玩家端升级为 **0.3.2**，Bootstrap Agent 保持 **0.1.2**。这是 0.3 大版本的第一个正式发行，玩家端界面整体重新设计，服主可以在管理端编辑首页焦点图、服务器卡片、活动、内容页面和画廊。

## 主要更新

### 玩家端：全新首页

- **首页焦点图**：每张可以设置标签、眉题、标题、简介、背景图和按钮，按钮可以打开页面、公告或网址。每 7 秒切换一次，鼠标停在上面时暂停。数量不限，超过 6 张时切换器会变成紧凑的翻页器。没有设置焦点图时，首页显示欢迎标题和最新公告。
- **服务器卡片**：显示服务器图标、版本、彩色 MOTD（支持 `§` 颜色码，过长时自动换行）、实时在线人数和延迟，以及社区按钮（QQ 群、Discord、KOOK、哔哩哔哩、官网等，点击打开链接或复制群号）。服务器地址可以显示在卡片里、焦点图按钮旁，也可以不在首页显示。查询服务器失败不影响更新和启动。
- **活动卡片**：显示下一场活动，并实时倒计时，进行中会单独标出。活动数量不限。
- **右侧卡片自动排布**：宽度随窗口变化。空间不够时，服务器卡片先变紧凑，人数和延迟并到标题行、地址收起，尽量保住活动卡片；更新卡片始终完整显示。
- **标题栏**：左上角默认显示梦鱼更新器图标，服主可以换成自己的图标。右侧显示玩家的像素头像和名字；音乐播放器可以选曲、暂停和单曲循环。

### 玩家端：更新卡片与本地管理

- **更新卡片重新设计**：小鱼沿着水线游动表示进度。检查、下载、玩家端自更新、完成、出错和离线都有各自的样子。
- **本次更新一目了然**：完成后可以展开“本次更新”，显示版本、发布时间，以及按“新增 / 更新 / 修复 / 调整 / 移除”标记的更新说明，还有安装、删除、备份、保留了多少文件。底部可以直接打开更新记录、运行记录和本地文件。
- 出错时提供“打开目录”“重试”和“仍然启动”。“保持打开”按钮带倒计时圈。
- **更新与本地管理面板**改成左侧分类栏，包括本次更新、更新记录、运行记录、可选内容、文件管理、模组启停、自选模组、备份与恢复。

### 玩家端：内容页面与外观

- **公告页**改为杂志式排版：最新一篇做成带封面的头条，其余是卡片网格；文章页右侧有目录和更多公告。
- **新增内容块页面**：文字、卡片、步骤、规则列表、团队成员、常见问题、数据、横幅、大图和小画廊共 10 种内容块，适合写服务器介绍、玩法和规则。
- **新增画廊页面**：可以按分类筛选，拼贴排列，点开看大图，大图会显示作者、坐标和说明。
- **外观**：卡片圆角可选圆润、柔和、方正，质感可选毛玻璃、实色、通透。全部文字改用鸿蒙字体，大标题使用衬线字体。

### 管理端与桌面版

- **“玩家端设计”新增分组**：首页焦点与活动、服务器卡片、展示图片、导入与导出。页面编辑支持内容块页和画廊页，旁边实时预览真实的玩家端，可以直接点击预览里的导航。
- **展示图片**：上传后，焦点图、服务器图标、左上角图标、页面和画廊都可以直接选用。图片随下一次整合包发布交给玩家。
- **导入与导出**：整套展示内容可以导出成 JSON 文件，也可以从 JSON 导入；导入时逐条列出哪里写错了。仓库里的 [展示内容规范](https://github.com/hanhanyu666/DreamingFish-Updater/blob/v0.3.1/docs/showcase/README.md) 附带 JSON Schema、完整示例和写给 AI 的提示词，可以让 AI 按服务器情况写好再导入。
- **“改动与发布”会列出玩家端设计的改动**：标题、焦点图、服务器卡片、配色、页面等保存后就对玩家生效，标为“已生效”；背景图片、展示图片和启动音乐要发布新版本才会生效，标为“待发布”。终端的 `project scan` 和 `project publish` 也会显示这些改动。

## 更新教程

### 升级前备份

1. 等导入、发布和部署包下载完成后再升级。关闭窗口通常只是隐藏到托盘；要替换程序文件时，用连接页的“退出桌面端”或托盘菜单退出，让旧进程真正结束。
2. 桌面用户先在连接页点击“数据目录”，确认实际保存位置；自己选过管理目录的，另外备份那个目录。终端用户备份实际的管理端目录。要保留 `data/`、`management-settings.json`、`management-web-auth.json`（注册过账户时），以及桌面连接、日志和恢复记录；项目签名身份必须保留。
3. 外部的标准整合包目录和外部管理目录也要单独备份。加密“发布数据备份”不能代替上面的完整备份。不要用新包里的空目录覆盖已有数据，也不要把管理数据或签名私钥发给玩家。

### Windows 桌面安装版

1. 在桌面连接页点击底部的版本号“检查更新”，有新版本时选择“立即更新”，按提示关闭工作区并安装。更新完成后程序会自动重新打开。
2. 也可以下载 `dfs-admin-desktop-windows-x64-0.3.1-setup.exe`，完整退出旧桌面程序后运行安装包，沿用原来的安装位置。保留原有数据，不要选择删除或重置管理数据。
3. 打开原来的连接，确认连接页显示 **0.3.1**，原项目、账户和发布历史都在。桌面自带的本机管理核心会随程序一起更新；单独部署在服务器上的终端管理端，要按下面的终端步骤另外升级。

### Windows 桌面便携版

1. 下载 `dfs-admin-desktop-windows-x64-0.3.1.zip`，完整解压到一个固定目录。不要直接在压缩包里运行，也不要只复制里面的 EXE。
2. 完整退出旧桌面程序并做好备份后，用新版的程序文件、`core/` 等程序资源替换旧程序；保留旧目录里已有的 `data/`，不要用新包里的空数据覆盖它。
3. 如果搬到新目录，要连同原来的 `data/` 一起搬；原来放在外部的管理目录和整合包目录仍要保留，必要时重新定位连接。运行 `DreamingFishAdminDesktop.exe`，确认版本和原有项目都正确。

### Windows / Linux 终端管理端

1. 下载对应系统的 `dfs-admin-windows-x64-0.3.1.zip` 或 `dfs-admin-linux-x64-0.3.1.zip`。先按原来的方式（终端、systemd、Docker 或启动脚本）停止管理端进程；如果网页管理和公共下载服务是分开运行的，两个都要停。不要在旧进程还在运行时混用新旧程序文件。
2. 解压新包，替换原目录里的程序、`app/`、`runtime/`、`support/` 和对应的启动脚本；保留 `data/`、`management-settings.json`、`management-web-auth.json`、恢复材料和外部标准整合包目录。继续使用原来的服务参数、端口和反向代理配置。
3. 按原来的方式启动。在管理端目录检查版本：Windows 运行 `.\DreamingFishAdmin.exe --version`，Linux 运行 `./dfs-admin --version`，确认输出 **0.3.1**。Linux 上如果解压工具没有保留执行权限，给 `dfs-admin` 和 `runtime/bin/java` 补上执行权限。
4. 重新打开或刷新管理网页，确认原账户、项目和发布历史都在。使用单独公共下载服务的，按原来的部署方式恢复服务，并检查玩家更新地址能访问。想在自己电脑上使用新的展示内容编辑，还要升级桌面程序。

### 玩家端是否需要更新

1. **本次需要发布新的玩家端程序 0.3.2，玩家才能看到新版界面。** 先把管理端升级到 0.3.1，再在管理端进入“发放 → 玩家端程序”，上传 `dreamingfish-player-windows-x64-0.3.2.zip`，点击“检查发行包”，确认识别出的版本是 0.3.2、平台是 windows-x64 后“确认发布”。
2. 发布后，已有玩家下次联网打开更新器时，会自动下载新程序并重新启动，不需要重新安装，也不需要重新制作或发放整合包。Bootstrap Agent 仍为 0.1.2。已经发布过的玩家端版本号不能重复发布。
3. 原来的标题、配色、页面和公告都会保留。新增的设置都有默认值：服务器地址显示在服务器卡片里，左上角显示梦鱼更新器图标。焦点图、服务器卡片和活动可以在“玩家端设计”里慢慢添加。
4. 只有首次发放或制作新的完整整合包快照时，才需要生成薄部署 ZIP 并合并到对应实例；普通的在线模组和配置更新继续走检查、发布流程，不用每次重新打包整个客户端。

### 升级后检查

1. 确认实际使用的管理端和桌面程序都是 **0.3.1**，原项目、账户、签名身份和发布历史完整。如果显示空项目或新建账户向导，先核对连接和数据路径，不要直接重新建库或删除恢复记录。
2. 在“发放 → 玩家端程序”确认当前玩家端是 **0.3.2**。打开“玩家端设计”，实时预览应显示新版首页；修改一项设置并保存后，“改动与发布”应列出对应的玩家端设计改动。
3. 用测试实例打开一次更新器，确认它自动升级到 0.3.2 后显示新版首页。填写了 Minecraft 服务器地址时，服务器卡片应显示在线人数和延迟。
4. 检查公共下载服务和项目的玩家更新地址，用测试实例完成一次整合包更新。签名、整合包维护规则和最低玩家端版本不需要因本次升级调整。

完整部署与故障排查可以参考 [快速开始](https://github.com/hanhanyu666/DreamingFish-Updater/blob/v0.3.1/docs/QUICKSTART.md)、[部署参考](https://github.com/hanhanyu666/DreamingFish-Updater/blob/v0.3.1/docs/DEPLOYMENT.md) 和 [展示内容规范](https://github.com/hanhanyu666/DreamingFish-Updater/blob/v0.3.1/docs/showcase/README.md)。
