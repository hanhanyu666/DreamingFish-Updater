# DreamingFish Update System 最简使用教程

这份教程用 Web 管理界面完成日常操作。加密备份、自动化命令和故障处理请看
[完整部署参考](./DEPLOYMENT.md)。

## 先记住五句话

1. 标准整合包目录里放什么，管理端就管理什么；不要求同时存在 `mods` 和 `config`。
2. 玩家端程序只在更新器自身升级时发布，不是每次更新模组都发布。
3. 玩家实例只在制作新的完整整合包下载文件时准备，不是每次在线更新都准备。
4. 公共下载服务默认是 `0.0.0.0:8080`，Web 管理页面固定是 `127.0.0.1:18080`，两者不是同一个端口。
5. 玩家只需安装服主做好的整合包，然后正常点击 PCL 的“启动游戏”。

## 准备三个目录

路径可以自行修改：

```text
D:\DFSAdmin       管理端程序和自动生成的 data
D:\DFSSource      服主希望更新器管理的文件
D:\MyModpack      服主电脑上准备发给玩家的完整 Minecraft 实例
```

`D:\DFSSource` 不需要是完整游戏目录。只管理模组时只放：

```text
D:\DFSSource\
    mods\
```

只管理部分配置时也可以只放：

```text
D:\DFSSource\
    config\
        某个模组的配置目录\
```

管理端不会自行创建 `mods` 或 `config`，也不会管理标准目录之外的玩家文件。

## 第一次部署

### 1. 启动管理端和 Web 页面

把 `dfs-admin-windows-x64-0.1.14.zip` 解压到 `D:\DFSAdmin`，双击：

```text
D:\DFSAdmin\DreamingFishAdmin.exe
```

第一次运行时：

- HTTP 监听地址直接回车，使用 `0.0.0.0`；
- HTTP 监听端口直接回车，使用 `8080`；
- 询问是否立刻创建项目时可以输入 `N`，稍后在 Web 页面创建。

进入主菜单后选择：

```text
[10] 启动 Web 管理界面
```

管理端位于当前电脑时，在浏览器打开：

```text
http://127.0.0.1:18080/
```

管理端位于远程服务器时，先在自己的电脑建立 SSH 隧道：

```powershell
ssh -N -L 18080:127.0.0.1:18080 <服务器用户>@<服务器地址>
```

SSH 使用非默认端口时再加 `-p <SSH端口>`。保持这个终端运行，然后仍然在自己电脑打开：

```text
http://127.0.0.1:18080/
```

不要在云安全组或防火墙中开放 `18080`。Web 管理端只允许本机或 SSH
隧道访问。按 `Ctrl+C` 会停止 Web 管理界面并返回管理端主菜单，不会退出整个管理端。

### 2. 创建项目

在 Web 首页点击“新建项目”，填写：

| 字段 | 示例 |
| --- | --- |
| 项目 ID | `building` |
| 项目显示名称 | `梦鱼建筑服` |
| 标准整合包目录 | `D:\DFSSource` |
| 玩家访问公共 HTTP 地址 | `http://你的公网IP:8080` |
| 强制同步一级目录 | 第一次留空 |
| 服务器地址 | 你的 Minecraft 服务器地址 |

公共地址必须能从玩家电脑访问，不能填写 `127.0.0.1`、`localhost` 或
`0.0.0.0`。如果云平台把公网 `39988` 映射到服务器内网 `8080`，这里应填写：

```text
http://你的公网IP:39988
```

创建完成后，把实际要管理的目录和文件放入 `D:\DFSSource`。

### 3. 发布一次玩家端程序

这一步在玩家端 `0.1.13` 期间只做一次。以后只更新模组或配置时不要重复做。

把 `dreamingfish-player-windows-x64-0.1.13.zip` 解压到临时目录，例如：

```text
D:\DFSPlayerTemplate
```

在 Web 左侧进入“玩家端程序”，只需填写：

| 字段 | 填写 |
| --- | --- |
| 平台 | `windows-x64` |
| 最低 Bootstrap Agent 版本 | `0.1.2` |
| 玩家端发行包解压根目录 | `D:\DFSPlayerTemplate` |

管理端会自动读取 `0.1.13` 版本号并定位
`DreamingFishUpdater\app\0.1.13\DreamingFishUpdater.exe`。确认发布后，临时解压出的
`D:\DFSPlayerTemplate` 可以删除；管理端已经把程序按内容保存进 `data`。

### 4. 发布第一个整合包版本

进入“扫描与发布”，先点击“扫描源目录”。检查新增、修改和删除列表无误后填写：

```text
显示版本：1.0.0
最低玩家端程序版本：0.1.13
更新记录：首次发布
```

点击“发布整合包”，再次确认。Web 页面按 UTF-8 传输中文，不需要使用
`@更新记录.txt` 的终端兼容写法。

发布是不可变的。内容有误时不要修改旧发布，应修正标准目录后再发布一个新版本。

### 5. 生成首次部署包并合并到本地实例

这一步不要求远程管理服务器拥有完整 Minecraft 实例。进入 Web 左侧“玩家实例”，
使用上方的“生成首次部署包”，填写：

| 字段 | 填写 |
| --- | --- |
| 输出父目录 | 管理服务器上的空闲目录，例如 `D:\DFSOutput` |
| 平台 | `windows-x64` |
| 原整合包对应版本 | 选择刚发布的 `1.0.0` |

点击“生成部署包”。管理端会生成一个新目录，其中只有更新器程序、Agent、真实
项目绑定、项目封面和 `1.0.0` 的签名基线，不会重复放入 `mods`、`config` 或
Minecraft 本体。

把这个新目录完整下载到服主电脑，再把目录内的全部内容合并到
`D:\MyModpack`。隐藏目录 `.dreamingfish-bootstrap` 不能漏掉。普通玩家不执行
此步骤，他们拿到的应该是已经合并完成的整合包。

如果管理端能直接访问 `D:\MyModpack`，也可以使用同页下方的“制作玩家实例”。
它会直接写入绑定、补齐所选发布文件并生成基线；两种方式二选一即可。

### 6. 给 PCL 写入启动参数

在 PCL 中打开这个具体版本的设置，把下面一条加入该版本的 JVM 参数：

```text
-javaagent:"{verpath}.dreamingfish-bootstrap/bootstrap-agent.jar"
```

必须保留 `{verpath}`，不要改成当前电脑的绝对路径。导出整合包后，确认
PCL 的版本设置也被带入，玩家不应该再手动填写。

### 7. 启动公共下载服务

回到 Web 首页，点击“启动下载服务”。终端和 Web 管理进程需要保持运行。

先在管理服务器访问：

```text
http://127.0.0.1:8080/healthz
```

再从另一台电脑访问：

```text
http://你的公网IP:8080/healthz
```

正常会看到：

```json
{"status":"ok"}
```

最后用 PCL 启动一次 `D:\MyModpack`，确认更新器出现、Minecraft 获得启动
许可，再导出并发布完整整合包。

## 以后更新模组或配置

普通在线更新只做三件事：

1. 修改 `D:\DFSSource` 中的文件；
2. 在“扫描与发布”中重新扫描并检查差异；
3. 填写新显示版本和更新记录后发布。

不需要再次发布玩家端程序，不需要再次制作玩家实例，也不需要让玩家重新下载
完整整合包。玩家下次启动游戏时会按文件差异更新，只下载本机缺少或内容变化的对象。

也可以直接在 Web 左侧“源文件”中管理 `D:\DFSSource`：从自己当前电脑拖入或
多选上传文件，或用 `…` 选择 VPS 本机文件。覆盖和移除前的旧文件会归档到
`D:\DFSAdmin\data\source-archive\`。一次上传多个文件时，整批只扫描一次。

如果扫描结果中出现“移除”，发布前必须为每个文件选择一种处理方式：

- **删除玩家文件**：玩家更新时删除旧托管文件；玩家已经设置的普通本地豁免仍然优先。
- **放弃管理并保留**：不再下发该文件，但玩家电脑上的现有副本保持原样。

放弃管理记录会进入以后每个完整发布清单，因此从任意旧整合包直接更新到最新版时，
也不会误删这些文件。文件以后重新放回标准目录时，会自动恢复为托管文件。

## 什么时候重新制作完整玩家包

只有准备上传新的“完整整合包下载文件”时，才需要：

1. 在“玩家实例”中生成薄首次部署包，并选择该下载包实际对应的发布版本；
2. 下载后合并到本地完整实例；
3. 测试后导出整合包。

网站可以同时保留 1.1、1.2、1.3 等旧完整包。只要每个包制作时绑定了自己的
签名发布基线，玩家下载旧包后也能直接更新到当前最新发布，旧官方文件不会被误判成玩家自选文件。

## 强制同步先不要开

第一次部署建议让“强制同步一级目录”保持为空。普通同步中：

- 发布清单里的文件缺失或损坏时会恢复；
- 玩家额外添加、且不在发布清单里的文件会保留并提醒；
- 玩家可以在玩家端为不兼容文件设置本地豁免。

只有明确要求某个一级目录与远程完全一致时，才在“项目设置”中填写例如
`mods`。只要求一个具体文件不能被玩家豁免时，在“扫描与发布”的“单文件强制同步”
区域搜索并勾选该文件。单文件规则不会清理同目录的其它文件。

修改强制同步设置后必须扫描并发布新版本才会对玩家生效。目录或单文件强制同步
都优先于玩家本地豁免；强制目录中的额外文件会移入玩家备份，不会直接永久删除。

## 不想常驻 Web 页面

Web 页面没有定时轮询，空闲资源占用很低。仍想只使用终端时，可以按
`Ctrl+C` 返回主菜单，再选择：

```text
[9] 启动 HTTP 文件服务
```

按 `Ctrl+C` 同样只停止当前 HTTP 服务并返回主菜单。所有日常能力仍可从中文
交互终端完成；加密备份与恢复也只在 CLI 中提供。

## 升级管理端

停止服务并退出旧管理端，先备份 `data/` 和 `management-settings.json`，再用
新 ZIP 中的程序文件覆盖旧目录。若必须换到新目录，把旧 `data/` 放在新
`DreamingFishAdmin.exe` 同级；即使 `management-settings.json` 仍记录旧绝对路径，
新版也会检测有效的本地 `data/management.db` 并自动修正。不要把空 `data/`
误当成备份，也不要把管理端 `data/` 发给玩家。
