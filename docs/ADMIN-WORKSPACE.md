# 管理端工作区

管理端与桌面 0.3.2 起，网页和桌面共用 `admin-desktop/src/workbench/` 的 Vue 工作区，旧版网页及切换入口已移除。项目、账户、发布历史和管理数据继续沿用，无需重新创建。

## 打开工作区与旧网址

打开管理地址即可进入 `/workbench/`。需要登录时使用原有管理账户；公网访问仍需 HTTPS 或 SSH 隧道，账户与写入校验保持原规则。桌面启动与远程连接见[桌面说明](ADMIN-DESKTOP.md)。

根地址 `/`、`/index.html`、`/legacy`、`/legacy/` 和 `/legacy/index.html` 都通过服务器返回 302 跳转到工作区，跳转不缓存。旧书签中的 `project` 会保留，旧 `view` 转为对应的视图和分区：

| 旧页面参数 | 现在的位置 |
| --- | --- |
| `dashboard`、`content` | 文件 |
| `publish` | 改动与版本 → 待发布改动 |
| `project` | 设置 → 项目设置 |
| `personalization` | 玩家端设计 → 标题与品牌 |
| `player` | 发放 → 玩家端程序 |
| `distribution` | 发放 → 外部托管 |
| `instance` | 发放 → 发放整合包 |
| `settings` | 设置 → 服务设置 |

已经使用新版的 `view` 和有效 `section` 也会保留；未知视图或分区在工作区回到默认页。浏览器曾保存的“使用旧版”偏好不再影响入口。旧脚本、样式与旧图标不再提供，返回 404；管理 API、玩家下载地址和旧数据格式兼容继续保留。

## 文件与导入

左侧“文件”管理标准整合包目录。双击文件夹进入，工具栏提供返回上一级、搜索和筛选；单击文件查看详情。选中文件或目录后，在底部操作栏设置普通同步、强制同步、首次提供、可选内容或移出。目录设置会说明影响范围，详情显示继承来源。

“导入文件”选择当前电脑的文件，旁边菜单支持文件夹导入、从服务器导入和新建文件夹。远程连接时，“从服务器导入”和目录选择器浏览的是管理服务器。

1. 选择文件并核对完整保存路径。文件夹导入可控制是否保留外层名称，子目录结构保留。
2. 点击“上传并检查”，查看模组 ID、版本、同名文件和替换关系。
3. 对每项选择新增、覆盖、替换旧模组或跳过，再确认导入。
4. 查看完成结果，到“改动与版本 → 待发布改动”检查并发布，玩家才会收到内容变化。

替换会归档旧源文件，并沿用对应维护方式与可选组；冲突设置或不相干的同名内容不会被静默覆盖。已导入项不重复写入；“跳过”不算导入成功。连接中断后使用原暂存 ID 复查，不重复上传或提交未知结果。浏览器刷新丢失本地文件时需要重新选择；服务器导入保留服务器路径。

任务与弹窗固定所属项目，切换项目时不会把迟到结果写到另一个项目。暂停停止后续文件任务；已经提交的文件不会因此撤销。导入归档与恢复收据位于管理数据内，升级或迁移时随 `data/` 保留。

## 检查、发布与历史问题文件

“改动与版本”分为待发布改动、发布版本、操作记录和历史问题文件。检查后核对文件、维护规则、移除动作及玩家端设计的改动，再填写显示版本和更新说明。最低玩家端要求按能力计算，高级兼容设置可调整；过期的检查结果需要重新确认。

“发布版本”查看历史、创建回滚发布。回滚生成一个新的不可变发布，不改写旧清单或签名。直接在服务器上改源文件后，应重新检查；发布校验发现后续变化时会拒绝旧确认。

“历史问题文件”从过去的文件版本中选择坏版本，填写原因并点击“要求玩家删除”。保存要求后还需要检查并发布。玩家端先备份，再删除匹配副本；此前已停止维护的文件也适用。“正在生效的删除与修复要求”可以结束相应要求，结束后同样需要发布。替换坏内容时先在文件页导入正确版本。匹配与备份语义见[简化维护说明](SIMPLE-MANAGEMENT.md)。

## 操作记录与恢复

操作记录可从顶部、文件工具栏的更多菜单、命令菜单或“改动与版本 → 操作记录”打开。这里显示本项目最近 200 条文件、设置和发布记录，支持搜索、筛选和查看前后变化。

可撤销操作先显示恢复预览，再确认。恢复会核对后续修改、原目录和归档，不覆盖后来的人工变化；已放入文件的新目录不能直接撤销。“恢复当前发布设置”恢复维护方式、可选内容和问题要求，不替换源文件、项目名称、地址或个性化。恢复已发布内容后，还要创建新的整合包发布。

新发布有精确设置快照；旧发布根据原签名内容重建有效规则，无法等价恢复时说明原因。直接在服务器文件系统改动不会自动产生操作记录。

终端使用同一套服务：

```text
dfs-admin project operations my-modpack
dfs-admin project operations my-modpack --undo 操作ID
dfs-admin project operations my-modpack --restore-published
```

后两项先预览再确认；脚本已核对预览时可加 `--yes`。参数式 CLI 支持 `--json`。恢复材料属于私有管理数据，不进入玩家部署包。

## 发放与玩家端设计

“发放 → 发放整合包”选择已发布版本和玩家平台，点击“生成并下载部署 ZIP”。桌面先选择本机保存位置；网页按浏览器能力提供另存为或下载列表提示。“写入管理端目录 / 准备现有实例”保留高级操作：在管理服务器生成目录，或直接准备它能够访问的实例。

“发放 → 玩家端程序”先“检查官方新版”，有更新的版本时点“发布给玩家”，管理端自动下载、核对官方签名并用项目签名发布，每个新版发布一次；也可以打开“官方发布新版后自动发布给玩家”，由运行中的管理服务定期完成同样的发布。已有发布版本时可暂停或恢复本项目所有平台的程序升级，暂停期间不会自动发布。手动上传发行 ZIP、从服务器解压目录发布收在可展开的高级入口，先检查识别出的版本、平台和启动文件，再批准并发布。详见[玩家程序自动更新](PLAYER-PROGRAM-UPDATES.md)。只检查不会让玩家升级。

“发放 → 外部托管”支持静态导出、WebDAV 和 S3 兼容对象存储。静态目录的“选择目录”浏览管理服务所在电脑或服务器。阿里云 OSS 请选择 Virtual hosted。暂停程序更新时，静态托管需要重新导出、上传并清理旧程序入口；界面分别显示策略、导出和最近一次内置上传状态。

填写历史按管理连接和项目保留最近 10 条，记住非秘密字段及 Access Key ID；不保存密码、Secret、临时会话令牌或地址里的凭据、查询参数。网页保存在当前浏览器，桌面保存在私有 `hosting-history.json`，不进入发行包。回填后重新输入临时凭据；历史保存失败不阻止正常上传，也不假报成功。

WebDAV 和对象存储的表单可以勾选“保存密钥，之后发布时自动上传”。上传成功后，管理服务把这次的地址和密钥保存在管理数据目录的 `keys/<项目>.hosting.json`，与项目签名私钥同等保护，加密备份时一起备份；网页只显示地址、存储桶、目录前缀、Access Key ID 或用户名，不再显示密钥。临时会话令牌会过期，不能保存。保存后，页面顶部显示“已保存上传设置”，可以“立即上传”、开关“发布后自动上传”或“删除保存的密钥”。自动上传开启时，管理服务在发布整合包、发布或暂停玩家端程序、自动发布、修改玩家端首页后约半分钟导出并上传，每 10 分钟再核对一次，内容没变就不上传；失败原因显示在卡片上，1 小时后或下一次发布时重试。只在管理服务运行时上传。

“玩家端设计”按标题与品牌、首页焦点与活动、服务器卡片、外观与背景、公告与页面、展示图片、启动音乐、导入与导出分区编辑，预览使用真实玩家前端。不同变更的生效方式在待发布改动中说明。内容规范见[展示内容说明](showcase/README.md)。

外层目录与配置合并在“文件”页，要求玩家程序至少 0.3.3。点击顶部的“外层目录”启用或进入外层文件；外层位置可以在示意文件树中点选，也可选择向上 1 至 8 级或直接填写相对路径和目录结构；树中标明游戏实例与更新根目录，示例不能代替玩家真实目录结构的核对。外层目录的设置随发布签名下发，已有玩家不需要重新分发；玩家端核对目录结构一致才写入，不一致时只跳过外层文件。配置合并规则在“导入文件”旁的下拉菜单里。具体限制、备份和生效时间见[目录与配置合并](CONTENT-ROOTS.md)。

## 服务、账户与后台任务

“设置 → 项目设置”修改标准目录与玩家更新地址；“检测”从管理服务器检查下载接口，不能代替玩家电脑的公网测试。“设置 → 服务设置”管理监听地址、端口、公共下载服务及存储清理；修改网页监听配置后按提示重启服务。“设置 → 账户与安全”沿用原有账户与认证规则。

网页与桌面共用前端和 Java 管理 API。桌面本机模式使用内置核心与独立数据目录，远程模式调用已有服务。认证、签名、文件校验、发布与恢复在服务端执行；移除旧页面不会删除项目、历史或同步 API。

后台任务在支持 `application-tasks` 时使用稳定请求 ID 与持久结果。只取消尚未运行的排队任务；结果未知时先复查原 ID，不自动重放发布或外部写入。旧管理服务缺少新能力时显示升级提示，支持的同步 API 仍可使用。能力范围见[能力矩阵](CAPABILITIES.md)，存储与恢复保护见[存储说明](STORAGE.md)。
