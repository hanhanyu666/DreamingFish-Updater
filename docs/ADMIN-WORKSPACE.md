# 管理端工作区

管理端程序版本仍为 0.2.0。网页保留新版界面和旧版界面；新版与桌面端共用前端，三者共用项目数据和管理服务。桌面端的启动与远程连接见 [管理端桌面版](ADMIN-DESKTOP.md)。

## 选择界面

网页默认进入新版工作区，顶部“旧版界面”可以切回原来的布局；旧版顶部的“新版界面”用于切回来。浏览器会记住这次选择。切换时保留当前项目，文件、发布版本和操作记录也还是同一份。

新版沿用桌面程序的分栏结构：左侧活动栏切换视图，项目栏负责项目切换、发布状态和当前视图的目录或分区，内容区顶部显示视图名称，工具栏负责目录、搜索、筛选和导入，文件详情按需出现在右侧，选中内容后的维护方式、可选内容和移出集中在底部浮动栏。导入文件进入导入清单，发布、发放和玩家端设计各有自己的工作视图。底部状态栏显示待发布数量、当前版本、文件统计、导入进度和下载服务。操作记录可从顶部、文件工具栏的“更多”菜单或命令菜单打开。

也可以直接访问 `/workbench/` 打开新版，或 `/legacy/` 打开旧版。下面“管理内容”“检查并发布”等名称沿用旧版界面；对应的新布局操作见 [桌面工作区说明](ADMIN-DESKTOP.md)。

## 旧版界面的日常维护

主流程是“整理文件 → 查看改动 → 发布”。概览的步骤条按当前状态标出下一步；顶部状态标签区分尚未检查、已保存但待发布、需要重新检查和正在处理文件任务，点击即可进入“检查并发布”。保存文件或维护方式不会立即发布给玩家；文字、配色和自定义页面仍按原有个性化内容机制独立获取。

在“管理内容”选择目录，查看文件名、模组名称、版本和维护方式。目录可以统一设置普通同步、强制同步或首次提供；单个文件会注明是否继承目录设置。改变整个目录前，弹窗说明涉及的文件数和单独设置数量。单击文件名打开详情，查看完整路径、发布状态、规则来源、可选组和历史入口。

文件夹导航用层级连线表示父子关系，可以展开或收起。长名称在一行内省略，悬停可查看完整路径；文件夹使用蓝色层叠图标，文件使用白色折角纸张图标，服务器文件选择弹窗沿用同一套图标。空文件夹也可浏览。窄窗口通过“选择文件夹”打开目录导航，文件表保留名称宽度并允许水平滚动。搜索覆盖全部目录；批量操作出现于选择文件后，隐藏范围中的选择会计数提示。

进入文件夹后，点击文件区底部、“操作记录”左边的“返回上一级”，每次退回一层；根目录时按钮禁用。切换目录会清空搜索并把文件表滚回开头。

## 操作记录与恢复

文件列表下方的“操作记录”显示本项目最近 200 条设置修改、文件导入、替换、移除、新建目录和整合包发布。可按类别筛选或搜索，展开记录查看具体变化。

可恢复的操作提供“撤销…”入口，先列出要恢复的文件和设置，再确认。已撤销记录继续保留。设置修改、文件移除和覆盖通过管理端服务记录；直接在服务器文件系统修改文件不会自动产生操作记录。撤销会检查后续修改、源目录和归档完整性，不会覆盖后来变化的文件；新建目录已经放入文件时也不能直接撤销。

“恢复版本设置…”以当前最新整合包发布为基准，恢复维护方式、可选内容、额外文件处理和问题要求，逐项显示当前值与恢复值。它不替换源文件，不恢复项目名称、地址或个性化内容。恢复源文件用对应操作的撤销；恢复已经发给玩家的内容用回滚发布。已发布的内容撤销后，需创建新的整合包发布。

新发布在管理数据库中保存精确的维护设置快照，原签名清单保持不变。旧发布没有快照时，根据已签名内容重建有效规则；无法等价恢复的旧策略会提示原因。确认前出现后续设置、文件或发布变化时，需要重新检查。

终端使用相同服务：

```text
dfs-admin project operations my-modpack
dfs-admin project operations my-modpack --undo 操作ID
dfs-admin project operations my-modpack --restore-published
```

后两项显示恢复预览并要求确认。脚本已核对预览时可加 `--yes`。记录与源文件归档属于管理数据，迁移时随 `data/` 保留，不会进入玩家部署包。

参数式命令支持 `--json` 输出。撤销与恢复配合 `--json --yes` 时返回一个 JSON 对象，包含 `preview` 和 `result`，方便脚本或 AI agent 解析。

## 添加与替换文件

1. 在目标目录点击“添加文件”。默认保存到当前目录，可展开位置选择器或新建目录。
2. 从当前电脑选择文件/文件夹，或切换“从服务器导入”。目录结构会显示为每项的保存路径。
3. 点击“暂存并检查清单”。文件此时位于管理数据的私有暂存区，没有替换整合包目录中的文件。
4. 检查模组 ID、版本、同名文件和同一模组的旧文件，选择新增、归档覆盖、替换旧模组或跳过。
5. 确认导入，查看逐项结果，再到“检查并发布”发布整合包。

选择文件夹时，可控制是否保留外层目录名称，内部子目录始终保留。根目录选择 mods、config、resourcepacks 等标准目录时会保留这些目录；在 mods/ 中选择 mods 文件夹则默认放入其内容。提交前应以清单中的完整保存路径为准。

同 modid 的版本替换会归档旧文件，并沿用维护方式与可选组。替换属于明确的移出选择，最终发布检查会自动记录旧路径的移除动作。遇到不同旧文件的维护设置不一致，或目标同名文件属于其他内容时，不会自动覆盖，需整理或修改保存路径后重新检查。

每个文件可以独立重试。已导入项不会重复写入；连接中断后重新检查会识别已完成的导入。暂停会停止后续任务，已导入文件保留，已经提交的一项会完成。关闭任务窗口可以继续在后台处理，切换受当前进行中的导入约束；已发出的任务和弹窗仍固定原项目身份，迟到结果不会写入另一个项目。

“导入记录”列出本项目最近 40 次通过新清单完成的导入，可恢复导入前内容。恢复会验证归档、当前文件和维护设置，保护后续修改。已经发布的内容恢复后仍需发布新的整合包版本。记录与归档位于管理数据 source-imports/，迁移管理端时随 data 一起保留；它们不是玩家部署包的一部分。

## 发布与分发

- “检查并发布”显示内容、维护规则和移除动作的摘要。进入页面时，尚未检查或检查已过期（管理端记录到文件或设置变化）会自动检查；直接在服务器上改动文件后，管理端无法感知，发布时若被拒绝会自动重新检查并提示确认。显示版本按上一版本的末位数字自动建议，可直接修改。最低玩家端兼容版本默认根据检查结果填写，手动调整放在高级兼容设置。已有防回放、签名、旧客户端能力校验和过期预览检查继续生效。
- 改动列表的“文件大小”显示文件本身的体积；移除项显示上次发布时的文件大小，空文件显示 0 B。顶部“新增 / 更新文件大小”汇总本次新增和修改的文件。
- “项目设置 → 检测地址”从管理服务器读取当前项目更新接口，显示连接与响应结果。它不能替代玩家电脑的公网连通性验证。
- “玩家端个性化”按标题与品牌、外观、音乐、公告与页面分组。窄窗口切换编辑和真实预览；宽窗口保留并排预览。隐藏页面的必填项出错时会自动打开对应分组。
- “玩家端程序”可上传发行 ZIP，先识别版本、平台和程序目录，再确认签名发布。同版本或低于当前选中程序的包不能再次发布。从服务器已有解压目录发布仍保留在高级入口。ZIP 中的越界路径、大小写冲突及超量解压会被拒绝。
- “外部托管”先在三张卡片中选择仅导出、WebDAV 或对象存储，只展示对应表单，三种方式复用静态目录输入。账户和密钥仍只用于相应上传，不引入保存凭据的机制。
- “玩家实例”优先提供“下载部署 ZIP”。写入服务器目录和直接制作实例仍可使用；直接制作实例放在高级入口。平台使用选择控件，整合包历史版本仍由服主正确选择。
- 监听地址、端口等位于“系统设置”，与项目下载地址分开；概览提供待发布改动和下一步操作入口。

## 界面与管理服务

新版网页与桌面端共用 `admin-desktop/src/workbench/` 中的 Vue 前端。旧版的 app.js、文件工作区、文件传输和操作记录模块继续保留。两套前端通过同一组 API 使用 Java 管理服务：

| 模块 | 职责 |
| --- | --- |
| 新版工作区 Vue 前端 | 网页与桌面共用的导航、文件、发布、任务、发放、设计和设置 |
| 旧版网页模块 | 原版管理界面、文件清单、传输与操作记录 |
| SourceTransferService / PlayerPackageService / ProjectConnectionService | 与网页或桌面容器无关的 Java 应用服务 |
| WorkspaceOperationService / SourceOperationJournal | 持久化操作记录、受保护撤销和已发布设置恢复 |

本机桌面端启动内置管理核心，使用独立的管理数据目录和自动分配的本机端口；远程连接调用已有服务。桌面工作区加载程序内置资源，服务器网页通过 JAR 提供同一套新版资源。认证、写入校验、签名、文件维护和恢复仍在管理服务中处理。

历史问题文件的持续处理见 [简化维护说明](SIMPLE-MANAGEMENT.md)。


### 导入与项目会话修复（管理端 0.2.6）

项目切换会丢弃旧会话的迟到响应并关闭旧弹窗。保存与异步任务固定所属项目；加载失败时不会继续显示另一项目的可编辑详情。导入的“跳过”在客户端结束，不计入已导入数量，也不提交 SKIP。

任务记录保留请求 ID / 暂存 ID。超时显示“结果待确认”，重试先向原项目复查；已提交直接显示结果，检查失败仍刷新文件列表，再检查不会重复导入。刷新后无法还原浏览器 File 时需重新选择；服务器本地导入保留服务器路径。暂停只停止后续任务，取消当前上传不撤销已经提交的文件。发布预览被拒绝后重新检查，必须重新确认发布。

管理端导入将意图保存到 source-transactions，启动后的首次项目访问先恢复；源文件人工修改或归档丢失会阻止自动恢复和发布。请保留 source-imports 与 source-transactions 的全部材料，核对冲突后重试。收据提交后的取消或网络断开不改变已完成事实。

### 长任务与兼容

新工作区在管理端声明 `application-tasks` 时先保存稳定请求 ID，再发起任务并查询结果；确认响应丢失只查询原 ID，不重复提交。任务面板区分排队、运行、提交、成功、失败、结果未知、等待凭据和过期；仅排队项可确定取消。重启不自动重放未知写操作，凭据需再次提供。旧界面保留同步 API，导入的跳过 / 复查 / 已撤销契约一致。完整入口与后端条件集中在[能力矩阵](CAPABILITIES.md)。

目录聚合按文件变化建立一次索引；每页显示 200 项，搜索、排序和全选仍作用于完整筛选结果。跨页选择和过滤隐藏的选择有数量提示；方向键可跨页移动。中文采用系统字体回退，原字体许可证保留。

设置 → 服务提供存储统计和清理预览，明确选择放弃撤销后才会释放对应原件；详情见[存储说明](STORAGE.md)。
