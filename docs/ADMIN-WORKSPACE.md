# 管理端工作区

管理端程序版本仍为 0.2.0。网页与后续桌面 WebView 使用相同的页面、控制器和管理服务。

## 日常维护

主流程是“整理文件 → 查看改动 → 发布”。顶部状态区区分尚未检查、已保存但待发布、需要重新检查和正在处理文件任务。保存文件或维护方式不会立即发布给玩家；文字、配色和自定义页面仍按原有个性化内容机制独立获取。

在“管理内容”选择目录，查看文件名、模组名称、版本和维护方式。目录可以统一设置普通同步、强制同步或首次提供；单个文件会注明是否继承目录设置。改变整个目录前，弹窗说明涉及的文件数和单独设置数量。单击文件名打开详情，查看完整路径、发布状态、规则来源、可选组和历史入口。

文件夹导航用层级连线表示父子关系，可以展开或收起。长名称在一行内省略，悬停可查看完整路径；文件夹使用蓝色层叠图标，文件使用白色折角纸张图标。空文件夹也可浏览。窄窗口通过“选择文件夹”打开目录导航，文件表保留名称宽度并允许水平滚动。搜索覆盖全部目录；批量操作出现于选择文件后，隐藏范围中的选择会计数提示。

进入文件夹后，点击文件区底部、“操作记录”左边的“返回上一级”，每次退回一层；根目录时按钮禁用。切换目录会清空搜索并把文件表滚回开头。

## 操作记录与恢复

文件列表下方的“操作记录”显示本项目最近 200 条设置修改、文件导入、替换、移除、新建目录和整合包发布。可按类别筛选或搜索，展开记录查看具体变化。

可恢复的操作提供“撤销…”入口，先列出要恢复的文件和设置，再确认。已撤销记录继续保留。设置修改、文件移除和覆盖通过管理端服务记录；直接在服务器文件系统修改文件不会自动产生操作记录。撤销会检查后续修改、源目录和归档完整性，不会覆盖后来变化的文件；新建目录已经放入文件时也不能直接撤销。

“恢复版本设置…”以当前最新整合包发布为基准，恢复维护方式、可选内容、额外文件处理和问题要求，逐项显示当前值与恢复值。它不替换源文件，不恢复项目名称、地址或个性化内容。恢复源文件用对应操作的撤销；恢复已经发给玩家的内容用回滚发布。已发布的内容撤销后，需创建新的整合包发布。

新发布在管理数据库中保存精确的维护设置快照，原签名清单保持不变。旧发布没有快照时，根据已签名内容重建有效规则；无法等价恢复的旧策略会提示原因。确认前出现后续设置、文件或发布变化时，需要重新检查。

终端使用相同服务：

```text
dfs-admin project operations my-modpack
dfs-admin project operations my-modpack --undo 操作ID
dfs-admin project operations my-modpack --restore-published
```

后两项显示恢复预览并要求确认。脚本已核对预览时可加 `--yes`。记录与源文件归档属于管理数据，迁移时随 `data/` 保留，不会进入玩家部署包。

参数式命令支持 `--json` 输出。撤销与恢复配合 `--json --yes` 时返回一个 JSON 对象，包含 `preview` 和 `result`，方便脚本或 AI agent 解析。

## 添加与替换文件

1. 在目标目录点击“添加文件”。默认保存到当前目录，可展开位置选择器或新建目录。
2. 从当前电脑选择文件/文件夹，或切换“从服务器导入”。目录结构会显示为每项的保存路径。
3. 点击“暂存并检查清单”。文件此时位于管理数据的私有暂存区，没有替换整合包目录中的文件。
4. 检查模组 ID、版本、同名文件和同一模组的旧文件，选择新增、归档覆盖、替换旧模组或跳过。
5. 确认导入，查看逐项结果，再到“检查并发布”发布整合包。

选择文件夹时，可控制是否保留外层目录名称，内部子目录始终保留。根目录选择 mods、config、resourcepacks 等标准目录时会保留这些目录；在 mods/ 中选择 mods 文件夹则默认放入其内容。提交前应以清单中的完整保存路径为准。

同 modid 的版本替换会归档旧文件，并沿用维护方式与可选组。替换属于明确的移出选择，最终发布检查会自动记录旧路径的移除动作。遇到不同旧文件的维护设置不一致，或目标同名文件属于其他内容时，不会自动覆盖，需整理或修改保存路径后重新检查。

每个文件可以独立重试。已导入项不会重复写入；连接中断后重新检查会识别已完成的导入。暂停会停止后续任务，已导入文件保留，已经提交的一项会完成。关闭任务窗口可以继续在后台处理，当前项目在任务进行时不能切换。

“导入记录”列出本项目最近 40 次通过新清单完成的导入，可恢复导入前内容。恢复会验证归档、当前文件和维护设置，保护后续修改。已经发布的内容恢复后仍需发布新的整合包版本。记录与归档位于管理数据 source-imports/，迁移管理端时随 data 一起保留；它们不是玩家部署包的一部分。

## 发布与分发

- “检查并发布”显示内容、维护规则和移除动作的摘要。最低玩家端兼容版本默认根据检查结果填写，手动调整放在高级兼容设置。已有防回放、签名、旧客户端能力校验和过期预览检查继续生效。
- “项目设置 → 检测地址”从管理服务器读取当前项目更新接口，显示连接与响应结果。它不能替代玩家电脑的公网连通性验证。
- “玩家端个性化”按标题与品牌、外观、音乐、公告与页面分组。窄窗口切换编辑和真实预览；宽窗口保留并排预览。隐藏页面的必填项出错时会自动打开对应分组。
- “玩家端程序”可上传发行 ZIP，先识别版本、平台和程序目录，再确认签名发布。同版本或低于当前选中程序的包不能再次发布。从服务器已有解压目录发布仍保留在高级入口。ZIP 中的越界路径、大小写冲突及超量解压会被拒绝。
- “外部托管”先选择仅导出、WebDAV 或对象存储，只展示对应表单，三种方式复用静态目录输入。账户和密钥仍只用于相应上传，不引入保存凭据的机制。
- “玩家实例”优先提供“下载部署 ZIP”。写入服务器目录和直接制作实例仍可使用；直接制作实例放在高级入口。平台使用选择控件，整合包历史版本仍由服主正确选择。
- 监听地址、端口等位于“系统设置”，与项目下载地址分开；概览提供待发布改动和下一步操作入口。

## 桌面端复用边界

本次没有引入新的管理端 Tauri 外壳。界面功能按职责分离：

| 模块 | 职责 |
| --- | --- |
| app.js | 现有项目、维护方式、发布、账户和个性化领域交互 |
| file-workspace.js | 目录、文件表、详情、批量范围、历史与归档恢复 |
| file-transfer.js | 上传清单、检查、逐项导入、暂停与失败重试 |
| operation-history.js | 操作记录、撤销预览和已发布维护设置恢复 |
| admin-workflow.js | 传输接口、任务状态、页面分组、地址与发行包检查 |
| workspace.css | 共用布局、字体、控件、弹窗与响应式规范 |
| SourceTransferService / PlayerPackageService / ProjectConnectionService | 与网页或桌面容器无关的 Java 应用服务 |
| WorkspaceOperationService / SourceOperationJournal | 持久化操作记录、受保护撤销和已发布设置恢复 |

后续本机桌面壳可连接现有管理服务并加载同一工作区；远程管理模式连接远程服务。认证和写入校验保留在服务端，界面不直接操作玩家文件，也不把签名或文件维护逻辑复制到 Tauri 端。

历史问题文件的持续处理见 [简化维护说明](SIMPLE-MANAGEMENT.md)。
