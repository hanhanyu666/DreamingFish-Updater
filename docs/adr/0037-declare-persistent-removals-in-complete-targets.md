# ADR 0037 在完整目标中声明持续移除

日期：2026-10-03

状态：已接受

## 背景

根据上一安装清单推断删除，会让已经更新后恢复的副本与跳过版本的副本得到不同结果。玩家停用或自行管理后，副本也可能不在活动目录。服主希望简化界面，同时明确处理这些情况。

## 决策

新发布声明 `simplified-maintenance-v1` 并显式携带持续移除。普通移除以已有撤回载荷的资源范围表达，历史问题仍使用版本范围；两个范围由同一维护模型解释。客户端不再通过上一清单推断新规则的退场行为。

重新提供资源会结束普通移除，明确结束处理也允许玩家持有副本。问题版本保持有效，直到明确结束；回滚不能无意绕过这些要求。旧签名发布保持原语义，新目标要求至少 0.2.0 玩家端。

管理端释放、内容变化、持续要求和项目规则一起提交。停用副本的归档索引、文件移动与偏好使用同一恢复日志。普通移除与首次提供或豁免无关，明确动作优先且先备份。

## 取舍

发布描述需要长期保存已移除资源的身份与历史位置，不能按时间过期，否则旧包和长期离线玩家会漏掉要求。相比复用基线差异，这增加少量发布元数据，但让完整目标与实际副本决定行为，减少加入时间的影响。

默认配置自动更新不作为第四种新设置，可选内容仅组织普通同步，目录强制不再包含较弱例外。已发布内容继续兼容，旧项目的迁移要求在确认发布前展示。
