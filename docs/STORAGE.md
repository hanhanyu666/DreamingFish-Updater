# 管理数据、暂存和备份（管理端 0.2.6）

当前容量与清理入口是工作区“设置 → 服务 → 存储与清理”，或 CLI `storage`。先生成预览，再用相同选择和 stamp 确认；内容改变须重新预览。结果分别列出已释放和保留 / 失败项。

| 分类 | 默认保留与影响 |
| --- | --- |
| 当前发布对象、未发布品牌资源 | 保留，不自动删除 |
| 历史发布与玩家程序对象 | 保留，原签名发布不修改；回滚创建新发布 |
| 无已知引用的其他对象 | 保守保留，本轮清理不删除对象 |
| 未完成上传 / 解压 | 活动租约和资源锁保护；未知长度与 ZIP 展开不能绕过配额 |
| 未提交暂存 | 默认 24 小时；清理预览可回收过期项，保留 EXPIRED 小记录 |
| 已提交导入 | payload 可释放，stage / receipt 保留；before 原文件按撤销承诺保留 |
| 已发布玩家 ZIP | 发布对象和收据验证后释放 ZIP / bundle；重试原 ID 返回原结果 |
| 恢复意图与失败恢复材料 | 自动清理禁止删除；先解决冲突并恢复 |
| 已完成收据、任务状态 | 小型提交事实保留；任务详细结果最多 16 MiB / 项，按 256 项、64 MiB、7 天收敛，过期用摘要解释 |
| 已知临时导出 / 缓存中间文件 | 超期且无活动租约时可预览回收；未知目录保留 |

默认 `dfs.storage.stagingBytes=17179869184`（16 GiB）、`dfs.storage.recoverableBytes=68719476736`（64 GiB）、`dfs.storage.minimumFreeBytes=536870912`（512 MiB）、`dfs.storage.concurrent=4`、`dfs.storage.expiryHours=24`。这些为 Java 系统属性。容量预算按磁盘已有暂存加未释放预留量保守计费，可能提前拒绝临界请求；已有数据不因超额被删除。未知长度上传预留最大 4 GiB；玩家 ZIP 额外预留最大 4 GiB 展开空间，因此小 ZIP 也需要足够的预留预算。过期不等于曾经提交，无法确认的任务保持待确认。

选择“放弃文件导入的撤销归档”后，预览会逐项说明丧失的撤销能力；清理只删除 before，保留成功收据。不会顺带删除其他旧操作归档、历史发布、玩家备份或对象。

上传请求身份冲突只拒绝本次请求，不清理该 ID 先前已成功保存的暂存。失败清理只处理本次写入且尚无完整 stage 记录的副本；已有提交收据和恢复意图仍受保护。

导入或撤销复制中断后，本事务的半截 `.dfs-import-...tmp` 可以从已校验的 payload／归档重建。恢复仍先检查所有原目标和恢复材料；目标被人工修改、归档损坏、临时位置是目录或链接时会停止并保留材料，不能以“重建临时文件”为由覆盖玩家或服主的新内容。

清理失败留下的已提交 payload、玩家 ZIP / bundle 仍计入暂存占用；不能因完成状态而漏计。备份、部署 ZIP 和对象导入的已知临时前缀仅在无活动租约且超过保留期时回收，活动租约与恢复材料优先保护。未知文件不按年龄擅自删除。

加密管理归档用于恢复**发布能力**：SQLite、项目配置、密钥、整合包清单、玩家程序清单和对象。创建时协调活动项目提交；不一致的未完成导入先恢复或明确拒绝。它不包含标准源目录、运行设置、网页账户、桌面连接、source-imports、source-transactions、source-archive 或 source-operations。完整搬迁应另外保存这些目录、管理 home 和桌面 data；外部标准目录 / 数据目录独立搬迁。原密钥与信任序列必须保留。

备份生成同时需要数据库快照、ZIP 与加密中间文件空间；预算不足会明确拒绝，不能只按最终加密文件大小估算。恢复先验证签名与内容，再替换；安装和回退均失败时保留原目录和验证后的候选目录，报告实际位置。

发布对象按顺序写入时，整次发布只预留最大待新增对象的暂存峰值；对象移入正式库或成功删除临时副本后归还临时计量。配额限制的是同时占用的暂存，不把整个整合包累计流量当作暂存峰值。每块仍计量并检查磁盘余量，完整哈希、路径检查与强制落盘保留；租约仅复用已确定文件系统的余量查询。

桌面与启动脚本默认 `-Xms64m -Xmx512m`。`DFS_JAVA_HEAP_MB` 可设为 128–16384 的整数，桌面及 `dfs-admin.cmd` / `dfs-admin.ps1` / Linux `dfs-admin` 会按独立参数传递；Windows `DreamingFishAdmin.exe` 使用打包时的默认 512 MiB。`Xmx` 不是整个 Java 进程、WebView 或桌面总内存的上限；配置下界也不代表所有项目都能在该预算运行。
