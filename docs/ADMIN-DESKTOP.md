# 管理端桌面版

版本 0.2.5，当前提供 Windows x64 版本。

桌面版使用独立的工作区界面。最左侧是图标活动栏，悬停显示名称，底部按钮可以改为显示文字；上方切换文件、改动与版本、发放和玩家端设计，下方是下载服务、深浅色、设置和账户菜单。旁边的项目栏用于切换和新建项目、查看发布状态，并列出当前视图的内容：文件页显示文件夹树和可选内容，其他页面列出各个分区；底部显示当前发布版本。内容区顶部显示当前视图和项目名，右侧是操作记录和搜索命令；左侧按钮可以收起项目栏，收起后项目切换和分区标签移到内容区顶部。文件详情、发布说明和玩家端编辑以面板形式在右侧按需出现，选中内容后的常用操作集中在底部浮动栏。窗口底部的状态栏显示待发布数量、当前版本、文件数与大小、导入清单进度和下载服务状态，点击可直接打开对应页面。内容区是一张圆角卡片，卡片内的面板以细线分隔；窗口较窄时项目栏改为浮在内容上方。文件列表按类型显示彩色图标，便于区分模组、配置、脚本和压缩包。

安装版从开始菜单或桌面的“梦鱼更新管理”打开，便携版双击 `DreamingFishAdminDesktop.exe`，选择一个管理连接，就能进入工作区。标题栏支持拖动、最小化、最大化和收到托盘；顶部“连接”可以回到连接页。Windows 11 上窗口使用系统圆角，最大化时恢复直角。

## 在本机维护

1. 选择“本机管理”，填写一个便于识别的连接名称。
2. 第一次使用可以保留默认管理数据目录。已经用过命令行或网页管理端，则点击“选择目录”，选中原来保存 `management-settings.json` 的目录。
3. 点击“打开工作区”。第一次进入工作区，完成账户设置，再创建整合包项目。
4. 在项目里选择整合包标准目录，开始整理文件。玩家访问的更新地址可以创建时填写，也可以发布版本或生成部署包前，在“设置 → 项目”里补上。

连接页选择的是**管理数据目录**，项目里选择的是**整合包标准目录**。例如，`updater-management/` 保存管理设置、账户和发布数据，`modpack-source/` 保存要提供给玩家的模组与配置。

两个目录都要单独准备。管理数据目录只能是空文件夹或原来的管理端目录，选了放着其他文件的文件夹（例如“下载”）时，桌面端会提示换一个。整合包标准目录也只放要发布的内容，不要直接选桌面、下载或整个磁盘；里面有读不了的文件或失效的目录链接时，创建项目会指出是哪一项。

桌面程序自带 Java，不用另外安装。管理工作区使用自动分配的本机端口；原来的网页端口设置继续保留。退出桌面端后，项目、密钥、账户和发布记录仍留在管理数据目录里。下次打开相同目录即可继续维护。

## 数据保存在哪里

桌面端优先使用程序文件夹里的 `data`；无法写入时使用下述 AppData 回退位置。连接页显示本次实际位置。这里保存：

- `connections.json`：连接记录；
- `logs\`：运行日志；
- `management\`：默认的管理数据目录，保存项目、签名密钥、账户和发布记录；
- `webview\`、`webviews\`：界面缓存。

升级和卸载都不会删除 `data`。卸载页的“同时清理界面缓存”只清理缓存，不动项目和发布数据。便携版把整个文件夹拷到其他电脑或 U 盘，连接记录和默认管理数据会一起带走。连接页左下角的“数据目录”可以直接打开这个文件夹。

如果程序装在 `C:\Program Files` 这类没有写入权限的位置，数据会改存到当前用户的 `AppData\Local\cn.dreamingfish.admin.desktop`，连接页会提示实际位置。

0.2.3 及更早的版本把数据放在 AppData。新版本会尝试迁移到程序旁的 `data`；0.2.6先记录可恢复的 `migration.json`，复制并逐字节核对，再提交管理设置与连接记录，最后清理源目录。提交前失败继续使用记录中的旧根；提交后清理失败使用新根并提示保留位置。目标已有数据时不覆盖；管理数据被占用、路径歧义、磁盘不足或链接冲突会明确拒绝。恢复记录与 `logs/desktop.log` 可用于核对实际阶段，不能承诺没有残留。

便携版压缩包里是一个“梦鱼更新管理”文件夹。请把整个文件夹解压到固定位置（例如 `D:\梦鱼更新管理`）再运行；直接在压缩包里打开，或者只拿出 exe 运行时，程序会提示先解压，不会写入任何数据。便携版第一次打开时会提醒：数据就在当前文件夹的 `data` 里，不要删除。`data` 里也放了一份“请勿删除”的说明。

## 连接服务器

连接页提供“管理地址”和“SSH 连接”：

- **管理地址**：填写已有的 HTTPS 管理地址，或者已经转发到本机的 `http://127.0.0.1:端口/`。
- **SSH 配置**：填写系统 OpenSSH 中的配置名称，例如 `my-server`，以及服务器上的管理端口，默认 `18080`。服务器上需要先启动网页管理端。

SSH 连接沿用你的系统配置、密钥和认证代理。先在终端确认 `ssh my-server` 能正常连接；桌面端不会弹出终端让你输入 SSH 密码。第一次连接服务器时，也先在终端完成主机身份确认。

本机与远程使用同一套桌面界面，文件、项目和发布记录来自当前连接的管理端。旧基本连接要求管理端 0.2.1 或更新；本轮恢复与任务能力还要求 API v2 对应能力，详见[能力矩阵](CAPABILITIES.md)。

进入远程工作区后，仍使用服务器上的管理账户登录。连接记录只保存名称、地址、目录与端口，不保存登录密码或私钥。

左侧列出保存的连接。选择连接后可以修改信息、打开工作区，也可以从更多菜单移除记录。

## 整理文件与导入

双击文件夹进入，使用工具栏中的后退、前进和“返回上一级”浏览目录，`Alt + ↑` 或 `Backspace` 也能返回上一级。项目栏中的文件夹树会自动展开当前目录，有待发布内容的文件夹带有圆点。收起项目栏或窗口较窄时，工具栏下方改为列出顶层目录和可选内容。

单击选择文件，按住 Ctrl 或 Shift 选择多项。选中后，底部浮动栏可以直接切换普通同步、强制同步和首次提供，也可以加入可选内容或移出；所选内容包含文件夹时，会先列出范围再确认。双击文件、点击“详情”或按 `Ctrl + I` 打开右侧详情卡片，查看路径、版本、模组 ID、规则来源和发布状态；右键文件也能打开同样的操作。可选内容从项目栏中的“可选内容”创建，名称不能重复，选中文件后加入；点击一组内容可以查看成员，并继续编辑说明和默认安装状态。

“导入文件”选择本机文件，旁边的菜单提供文件夹导入、服务器导入和新建文件夹。选择或拖入文件后，导入清单列出保存路径、大小、识别出的模组与覆盖关系。先点击“上传并检查”，核对后再“确认导入”。完成后可以直接点击“检查并发布”。

远程管理时，导入文件选择你电脑上的文件，“从服务器导入”浏览服务器上的文件。导入清单可以收起，左侧导航中的“导入”会显示待处理数量。

## 检查、发布与回溯

“改动与版本”用页面顶部的分段按钮切换待发布改动、发布版本、操作记录和历史问题文件。主区域查看本次新增、更新与移除，右侧发布卡片填写版本号和更新说明。文件大小表示实际文件体积，列表上方汇总本次新增与更新文件的大小；重复的发布提醒只显示一次。

操作记录保留文件与设置的变化。点击“撤销”先看恢复前后的内容，再确认；“恢复当前发布设置”可以把维护设置还原到当前发布。恢复后继续检查并发布，玩家才会收到变化。

内容区顶部、项目栏的“维护”分组、文件工具栏的“更多”菜单和命令菜单（`Ctrl + K`）都可以打开“操作记录”，支持搜索、按文件/设置/发布筛选、展开前后变化和撤销。

发布预览中的维护变化会写清文件路径和前后维护方式，例如“普通同步 → 强制同步”。文件夹额外文件处理、可选内容和问题要求也分别说明。

已经停止维护、留给玩家的文件，后来发现严重问题，可以在历史问题文件中按发布版本找到坏版本，保存处理要求。要替换玩家配置，则选中标准目录中的文件，在详情卡片或右键菜单中使用“修复玩家副本”。这两种处理都在发布后生效。

## 发放与玩家端设计

“发放”集中管理部署包、玩家端程序与外部托管。选择已发布的整合包和平台，生成部署 ZIP；上传玩家端发行包后，先识别程序版本、平台与启动文件，再确认发布。外部托管提供静态导出、WebDAV 和 S3。

从 0.2.8 开始，桌面版点击“生成并下载部署 ZIP”后，先在系统“保存玩家部署包”窗口选择本机路径；选择取消时不会生成或下载。文件完整写入后，页面显示保存路径、文件大小和“打开所在文件夹”。下载或写入失败时显示错误，保留已有的同名 ZIP，并清理此次未完成的临时文件。桌面下载沿用当前本机、HTTPS 或 SSH 连接的登录会话，保存位置始终是运行桌面程序的电脑，不是远程服务器。0.2.7 及更早的桌面程序需要升级才能获得此功能。

新网页在支持文件保存接口的浏览器安全环境中同样提供“另存为”，确认写入完成后显示所选文件名；浏览器不会向网页公开完整本机路径。其他浏览器和旧网页交给浏览器下载，并提示到下载列表核对进度、保存位置和拦截原因。

“玩家端设计”中间显示真实玩家端的实时预览，右侧卡片编辑标题、配色、背景、内容页和音乐。可以直接点击预览里的导航，查看修改后的页面；窄窗口在编辑和预览之间切换。

## 关闭、切换与退出

关闭工作区窗口会回到连接选择页，工作区在后台继续运行，点“返回工作区”即可回去；关闭连接选择页会收到系统托盘，正在处理的任务和本机下载服务继续运行。右键托盘图标，可以返回工作区、选择管理端或退出桌面端。再次双击程序也能打开连接选择页。

开着 RivaTuner Statistics Server（RTSS，常随 MSI Afterburner 一起运行）时，它会往桌面端里注入帧数显示，可能让界面黑屏或崩溃。0.2.6对浏览器退出、渲染退出和无响应统一按每窗口一分钟最多三次恢复，使用递增等待并记录原因。达到上限后停止自动循环，可通过托盘手动返回并重建窗口；真实 RTSS 注入仍需在对应环境验证。想彻底避免，请在 RTSS 里点“Add”添加 `DreamingFishAdminDesktop.exe`（安装版为 `dreamingfish-admin-desktop.exe`）和 `msedgewebview2.exe`，并把它们的 Application detection level 设为 None。

切换管理端前，在连接选择页点击“断开…”。本机管理会停止桌面端启动的管理服务和下载服务；远程连接会断开，服务器继续运行。然后选择另一个连接即可。

要完全结束程序，选择“退出桌面端”。如果管理端正在处理文件操作，会提示稍后再退出。本机核心或 SSH 连接意外中断时，程序会回到连接选择页，并提供重新打开和运行日志入口。

## 更新桌面程序

安装版启动后会检查 GitHub 上的最新版本。有新版本时，连接页顶部出现提示，点击“立即更新”即可：程序先关闭工作区、停止本机管理端，再下载并安装，完成后自动重新打开。也可以点连接页左下角的版本号手动检查。更新包带有签名，桌面端只接受签名正确的安装包。

便携版同样会提示新版本，点击“下载新版”打开下载页。退出程序后，用新压缩包里的文件替换程序文件，保留 `data` 文件夹即可。

0.2.2 及更早的版本没有自动更新，需要手动运行一次新的安装程序。它们以 `DreamingFishAdminDesktop` 的名称安装，安装新版时会先自动卸载这份旧程序，再装成“梦鱼更新管理”；旧版本放在 AppData 里的数据会在新版第一次打开时迁移过来。之后的版本都可以在程序里自动更新。

需要迁移到另一台电脑时，带上程序文件夹里的 `data`；如果项目用的是其他管理数据目录，也一并带上该目录中的设置、账户、`data/` 和项目标准目录。

Windows 使用系统 WebView2。安装版会在缺少 WebView2 时联网安装；便携版需要系统已有 WebView2。

文件维护和历史问题处理见 [管理工作区](ADMIN-WORKSPACE.md) 与 [简化维护说明](SIMPLE-MANAGEMENT.md)。


### 本地修复中的数据定位约定（2026-10-18）

连接配置 v2 将实际桌面 data 根目录内的 home 保存为相对路径，加载时相对于本次实际根解析；用户选择的外部 home 保持绝对路径。搬家后旧绝对路径有多个可能副本或原目录缺失时，连接页要求用选择目录按钮重新定位，不自动创建空库。标准源目录独立配置，不随 home 擅自改写。

迁移先保存 migration.json，再复制并逐字节核对，管理设置与 connections.json 均验证后才切换。失败提示中的“实际使用”路径由迁移结果决定；中途退出后按记录继续。源数据使用中的迁移被拒绝。损坏主配置可以从有效 previous 恢复，损坏原件和有效备份保留；无法恢复时明确报错。旧日志、未知文件或恢复证据未能清理时，会报告待清理，不能视作无残留。迁移额外需要一份管理目录的可用空间。

新保存的 Java 默认 dataDirectory 使用相对于 home 的 data；外部数据目录保持原身份。历史绝对 dataDirectory 缺失而本机又有数据库时，需在设置文件明确确认位置，避免静默改用另一副本。

### 任务与退出的边界

断开时取消本次连接所属的网络工作并在有限时间内回收；网络断开不撤销服务端已经提交的文件或发布。长任务通过原 ID 查询，未知结果不自动重发。关闭窗口继续后台工作与明确断开是不同操作。默认 JVM 堆为 64–512 MiB，完整内存还包括 Java 原生内存、桌面与 WebView；容量和配置见[存储说明](STORAGE.md)。

本轮修复均为本地候选，旧的 0.2.5 下载不因此更新。模拟故障与后台期限验收不等于真实 RTSS、硬断电或安装 / 升级验收，实际范围见[修复结果](reviews/2026-10-18-remediation-results.md)。
