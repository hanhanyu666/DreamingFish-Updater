# 当前能力与兼容矩阵

此表描述管理端 / 桌面 0.2.8、玩家端 0.2.2、Bootstrap 0.1.2 的能力。旧版本不会自动具备这些修复；玩家端修复需由服主发布新版玩家程序，本次 0.2.8 不增加新的玩家端修复。实现与验收见[修复结果](reviews/2026-10-18-remediation-results.md)和[补充修复](reviews/2026-10-19-followup-fixes.md)。

0.2.8 新增部署 ZIP 的本机另存为与保存结果反馈：桌面版确认完整写入后显示路径并可打开所在文件夹；新网页按浏览器能力提供另存为或下载列表提示，旧网页使用下载列表提示。具体行为见[桌面使用说明](ADMIN-DESKTOP.md#发放与玩家端设计)。

`GET /api/state` 提供 `apiVersion: 2`，并声明 `source-request-id`、`source-recheck`、`source-recovery`、`application-tasks`。旧版基本接口继续兼容；桌面原有的最低连接版本不等于具备上述修复能力。客户端按能力选择异步任务；缺失必要导入状态时提示升级，不把缺失字段解释为成功。旧同步 API 的网络中断仍可能留下已提交结果，须使用原 ID 或项目历史复查。

任务在排队前固定实例、项目和请求 ID。桌面代理保留 `Prefer: respond-async` 与 `X-DFS-Request-Id`；界面也能结束返回 200／201 的同步成功任务，不留下永久排队项。队列最多 8 项、工作线程 2 个；取消仅保证尚未运行的任务未开始，提交中或结果未知不能声称撤销成功。

CLI `tasks` 直接查询持久记录，不启动执行器、不改写任务状态。服务只有取得实例任务的排他租约、确认没有任何排队／执行任务持有预留后，才把遗留非终态转为结果未知或等待凭据；不会自动重放发布或外部写操作。其他进程仍在工作时保守显示最后保存的状态，不因新开查询进程判断其崩溃。只读 CLI 可以在确认实例无活动任务后返回“结果未知”的视图，原记录保持不变。取消另一个进程的排队任务应在任务所属的网页／桌面入口完成，独立 CLI 不接管它的执行器。

任务输入闭包、密码、令牌和私钥不持久化；详细结果有大小与保留期边界，过期 ID 仍能解释结果已过期。导入另有长期提交收据，不能当作缓存删除。

完整校验、安装目标验证和严格离线许可直接读取当前内容；跨调用索引只用于快速显示。维护规则、自行管理、首次提供、可选内容和持续移除语义保持原兼容约定。引擎自身在写游戏内容、恢复和维护状态之前取得游戏锁；游戏占用时可做只读检查，不能提交修复。玩家界面 CSP 与原生命令来源限制见[设计说明](V1-DESIGN.md)。

默认传输 / JVM / 存储预算、备份边界及完整搬迁清单见[部署参考](DEPLOYMENT.md)和[存储说明](STORAGE.md)。当前不做对象垃圾回收、程序内 HTTPS 终止、自动 CDN 配置或未来专属客户端功能。

管理端 0.2.7 的 HTTP 连接只有在请求体读到结束后才可复用；提前拒绝上传明确关闭连接，不自动等待或读取剩余上传。管理接口与公共文件服务共用此规则，慢传输与并发限制仍然生效。
