# 2026-10-18 修复的性能对照（执行于 2026-10-19）

基线来自 b8793bbae74ffd57be176bfd153cac0e38bc472c 的独立源码构建；包含当时完整前端资源。当前核心样本来自预算热路径修复后的同一 Java 实现，最终 UI 收尾用源码与类字节证明保持该 Java 实现不变。没有使用真实项目。

旧 / 新各三轮，按轮交错顺序。Windows 同机、32 逻辑 CPU、同一 Java 21.0.9、-Xms64m / -Xmx512m；本任务的编译和其他测量不并行。Core 10 ms 采样、桌面 20 ms 采样。工作集含共享页面，桌面多进程相加会重复计算共享页；私有提交内存另列。未把 Xmx 当作整个进程内存，未测 Java 实际堆占用。I/O 是进程逻辑读写量，不等于物理盘流量。

基线原生外壳与 Java 核心均从同一基线提交重新构建；两侧使用相同打包运行时和堆预算，每轮新建 home。六次隐藏检查均成功、所属端口关闭，未发现观测到的遗留 PID。CPU / I/O 是 20 ms 采样期间累计的进程计数，可能遗漏极短命进程，不是精确生命周期总和。

## 成本与限制

列表、重复初始化相关状态请求和目录派生得到改善，payload 不再随成功导入保留。首次发布墙钟中位数仍比基线慢约 17%，CPU 接近；presentation / 导入并非所有指标变快。新增持久化、资源计量和安全检查均保留，本次没有设备级 I/O 追踪，不能把差额精确归因到某一项。发布预算逐对象重建造成的超过 180 秒回退已修复，但仍有进一步优化落盘 / 路径开销的空间。

这些是单机人工数据，不推算在线玩家承载量。桌面隐藏启动、原生与 Java 分别测量，不能把合计工作集当作真实物理内存。真实 RTSS、硬断电、安装升级 / 自更新 / 卸载仍需专门环境。
