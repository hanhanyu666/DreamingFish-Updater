# Issue 2 小文件校验性能排查

本记录描述纳入 v0.3.3 的路径检查优化，管理端 / 桌面 0.3.3、玩家端 0.3.4。用户反馈 TACZ 枪包的小文件校验慢，截图显示整合包共 5,573 个文件、约 1.32 GiB，其中 TACZ 有 4,795 个文件。未取得用户的完整整合包或机器上的耗时记录。[Issue 2](https://github.com/hanhanyu666/DreamingFish-Updater/issues/2)

## 原因与修改

`PathSafety.assertSafePathTree` 原来对每个文件的每一级上级路径都执行两次真实路径解析。大量文件共享相同上级目录，Windows 下仍逐个重复这些调用，小文件自身的读取耗时反而很少。

修改后仍在每次调用时读取每一级路径的属性。Windows 默认文件系统的普通目录和文件直接完成检查，符号链接直接拒绝，其他重解析点继续比较真实路径。其他文件系统保留真实路径比较。属性读取失败会中止检查，仅路径不存在时继续。

这个判断依据 OpenJDK Windows 文件属性实现。非符号链接的重解析点，包括 junction，会被 `isOther()` 标记。代码同时限制在 Windows 默认文件系统且属性实现为 `DosFileAttributes` 的情况下使用快捷检查。[OpenJDK 实现](https://github.com/openjdk/jdk21u/blob/master/src/java.base/windows/classes/sun/nio/fs/WindowsFileAttributes.java)

文件内容仍逐个计算 SHA-256，检查结果不跨启动缓存。链接和目录重定向的检查仍在每次调用中执行。

## 本机测量

Windows、Java 25.0.3，同机连续测量修改前后三轮。每组包含 5,000 个 1 KiB 文件，使用类似 `tacz/tacz_default_gun/data/tacz/index/attachments/group-N/file-N.json` 的深层路径。文件预先写好，完整检查通过本机 HTTP 测试服务器获取签名清单，调用真实 `UpdateEngine.update`，各轮结果均为 `UP_TO_DATE`。采用空进度监听器。

修改前后使用等量、等内容、等层数的两个独立测试目录。每组独立签名，以避免测试密钥变化与旧安装记录冲突。先测旧实现，再测新实现，未清空操作系统文件缓存。编译和回归测试在该测量完成后执行。

| 测量项 | 修改前三轮，秒 | 修改后三轮，秒 | 前 / 后中位数，秒 |
| --- | --- | --- | --- |
| 单独读取内容并计算哈希 | 0.274、0.210、0.192 | 0.259、0.182、0.196 | 0.210 / 0.196 |
| 单独解析并检查路径 | 15.615、15.264、15.198 | 0.840、0.752、0.762 | 15.264 / 0.762 |
| 完整更新检查 | 17.011、17.058、17.049 | 1.734、1.394、1.357 | 17.049 / 1.394 |

该模拟场景中完整检查耗时减少约 92%。真实整合包还包含较大的模组文件，玩家的硬盘、杀毒软件、联网与界面事件开销也会影响速度。这些数值只能说明已复现的路径检查瓶颈，实际用户整合包的收益仍需回访验证。

本机探针与原始输出保存在未纳入版本管理的 `target/issue-2/SmallFilesProbe.java`、`before.log`、`after.log`。

## 验证范围

新增测试覆盖普通深层文件、尚未创建的子目录，以及已经检查过的目录被替换成同一整合包内 junction 后再次检查。已有测试覆盖 junction 作为根目录或中间目录时的拒绝。

发行包自带 Java 21.0.9 的精简运行环境无法直接启动 Maven Surefire，因为它没有测试框架依赖的 `java.management` 模块。改用按 Java 21 编译的本地入口直接调用三项路径测试，普通路径、缺失子目录、junction 根目录、检查后替换 junction 均通过。没有为测试更改发行运行环境。

首次完整 Maven 验证因源码变动导致旧前端资源的构建标识过期而停止。已按构建约定重建玩家界面、管理网页和管理桌面资源，然后重新执行 Java 回归测试。

最终 `mvn -B -o test` 成功，报告共 376 项测试，失败、错误和跳过均为 0。覆盖协议、更新引擎、管理核心、管理 CLI 和玩家应用，Bootstrap 模块编译成功。原始日志在本机 `target/issue-2/reactor-final.log`，Java 21 直接调用验证记录在 `java21-probe.log`。

## 交付范围

修复位于共用 Java 路径检查代码。玩家启动检查要获得提速，需要发行包含修复的新版玩家端程序。此记录对应的测量不包含真实启动器、原生窗口或 Linux 性能验证。
