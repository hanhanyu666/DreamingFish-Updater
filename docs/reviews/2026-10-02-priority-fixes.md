# 梦鱼更新系统优先问题修复记录

> 本文保留当时的设计或验证记录。0.3.0 已采用简化维护方案，当前行为见 [简化维护说明](../SIMPLE-MANAGEMENT.md)。

本轮实现了 2026 年 10 月 1 日审查中 F1–F8 的修复，并对齐领域术语、设计、部署、备份与升级文档。玩家端代码版本统一为 0.1.41，尚未发布。历史文件撤回属于下一阶段功能，未把它混入本轮缺陷修复。

## 修复内容与回归证据

| 问题 | 当前行为 | 回归证据 |
| --- | --- | --- |
| F1 路径联接越界 | 检查根与父目录的实际路径，拒绝符号链接和 Windows junction；创建、写入、恢复及清理前检查 | `PathSafetyTest` 使用真实 Windows junction，检查作为根、祖先及新建父目录时均拒绝；Bootstrap 验证也采用同一规则 |
| F2 释放副本丢失 | 停用副本记录玩家归属，重新启用时恢复或保留；同组件出现新官方文件名时仍保留已释放的历史副本 | `LocalModManagerTest` 验证普通释放恢复，以及有新托管文件名时历史副本保留 |
| F3 回滚丢释放记录 | 回滚继承当前释放路径，按既有大小写不敏感规则去重；重新接管的目标除外 | `PublishServiceTest` 验证继承、重新接管和大小写变化；`EndToEndUpdateTest` 验证两种旧基线均保留副本 |
| F4 双重恢复失败误删 | 替换和回退都失败时保留原目录与验证过的恢复目录，错误包含路径 | `BackupServiceTest` 注入安装失败及安装和回退双重失败，检查原数据未删 |
| F5 启停部分提交 | 文件移动、清理暂存与偏好共同写持久化事务；未提交恢复，已提交仅清理；共享恢复标记阻断不支持该日志的引擎 | `LocalModManagerTest` 验证中途 I/O 失败、偏好写入后崩溃、重复恢复、恢复前引擎拒绝以及只读模组启停 |
| F6 旧预览发布新策略 | 配置摘要、规则与移除决定进入预览；公开发布入口、Web 与 CLI 提交预览标识和摘要 | `PublishServiceTest` 验证规则、决定及预览替换失效；`AdminWebServerTest` 验证缺少绑定和旧绑定被拒绝 |
| F7 混合静态签名 | 无签名头时读取完整 `.signed` 文件；只有 404 才兼容 `.sig`，损坏文件不降级 | `StaticDistributionServiceTest` 验证混合旧指针仍采用完整新载荷、篡改阻断和旧目录兼容；展示配置也覆盖两种格式 |
| F8 响应体卡住 | 等待响应头及阻塞读取均支持取消，读取有期限，取消关闭流；下载器等待所有写线程结束后返回 | `HttpTransferTest` 验证头部与响应体取消、读取超时；`ObjectDownloaderTest` 验证停滞批次取消后可立即重试 |

隔离探针已改为检查修复后的行为，执行方式见[复现说明](D:/Desktop/DreamingFish-Updater/docs/reviews/repro/README.md)。正式回归测试使用临时实例、签名身份和本机 HTTP 服务，不操作实际服主项目或玩家数据。

## 文档对齐

- 新发布不再生成 `DEFAULT`；它只作为旧清单的 `LEGACY_MISSING_ONLY` 读取，不能声称实现“只首次下发”。
- 当前启动流程需要签名安装记录或分发基线。没有基线会阻断；已有基线但本地内容变化时的明确玩家选择不记为验证通过。
- 当前桌面主流程拒绝同实例已有游戏运行时再次启动；引擎单独接口的无修改检查不是桌面并发启动能力。
- 加密备份完整覆盖发布数据，运行设置、Web 账户及未发布源内容另行保存；双重恢复失败保留恢复候选。
- 预览规则变化和确认失效、单文件签名载荷及缓存规则、模组本地事务均已写入部署和设计文档。
- 原审查报告保留历史证据并注明已修复，整体重构草案保留尚未实现的资源模型与历史撤回。

## 升级注意事项

管理端升级后重新扫描旧的未发布预览，已签名发布和安装基线继续使用。玩家端需以 0.1.41 发布，不能覆盖已发布的同版本程序；现有玩家端下一次检查可先取得新程序。

静态托管需重新导出并完整上传 `.signed` 文件及其缓存配置。没有新文件的旧目录必须返回真实 404；新文件存在但不合法会阻断，不改信旧签名。新的首次部署包应使用本次构建的 Agent；Agent 不会在线自更新。

本轮没有进行真实 Minecraft 启动器验收或公网 CDN 切换验收；文件、恢复、签名及 HTTP 行为通过自动测试和隔离探针验证。
